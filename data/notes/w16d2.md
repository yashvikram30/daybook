# ML systems are mostly not ML code

Sculley et al. (_Hidden Technical Debt in ML Systems_): the model is a small box in a large system of data collection, features, serving, monitoring and config. Typical debt: **entanglement** ("changing anything changes everything"), **glue code** and **pipeline jungles**, **unstable data dependencies**, **feedback loops** (model output influences future training data), configuration sprawl.

# What changes in production

- **Training-serving skew:** features/preprocessing differ between experiments and the service: share code, test it.
- **Drift:** **data drift** (input distribution shifts) and **concept drift** (the right answer changes). Quality can fall **silently** because nothing crashes.
- **Versioning:** model, prompt, index/embedding model, data: all need versions and rollbacks.

# Detecting silent quality drops

1. **Quality canary:** a handful of golden questions run on a schedule against production; record **retrieval hit rate**, answer score, **abstention rate**; alert on drops.
2. **Online signals:** abstention rate, citation rate, retrieval score distribution, query length/language mix, user feedback (thumbs), latency and cost per request.
3. **Sample production traces** and grade them (human or LLM judge).
4. **Drift checks** on inputs (embedding centroid shift, new topics).
5. **Canary releases:** send ~5% of traffic to the new version, compare metrics, then promote or roll back.

# Gateway vs model service

- **Gateway (async Python, e.g. FastAPI + httpx):** auth, API keys, rate limits, quotas, request ids, routing, timeouts/retries/circuit breaking, caching, metrics: uniform for every backend.
- **Model service (Python):** retrieval, reranking, prompt assembly, generation orchestration: ML-ecosystem code; stateless, versioned, independently deployable.
- **When the RAG service is slow:** the gateway enforces a **timeout**, trips the **circuit breaker**, and **degrades** (cached answer, keyword-only result, or a clear "try again" with `Retry-After`) instead of queueing without bound.

# Steps

1. **FastAPI app** with `/healthz`, `/readyz`, `/v1/ask`, request-id header propagation, structured logs, a `/metrics` endpoint.
2. **Dockerfile:** slim Python base, install from the lockfile, non-root user, `HEALTHCHECK`/orchestrator probes on `/readyz`.

4. **Quality canary:** cron-style job posting ~10 golden questions to `/v1/ask`; records `hit@5`, `abstain_rate`, `answer_score` to metrics; alert if `hit@5` falls below a threshold over a window.
5. **Monitoring note:** list the dashboards (latency, errors, TTFT, tokens/cost, cache hit rate, canary scores) and alert rules with thresholds.

# Disjoint set union (union-find) and spanning trees

**DSU:** maintains groups with near-O(1) operations (`α(n)`, inverse Ackermann): **path compression** in `find`, **union by size/rank**.

```python
class DSU:
    def __init__(self, n: int) -> None:
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x: int) -> int:
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]        # path halving
            x = self.p[x]
        return x

    def union(self, a: int, b: int) -> bool:
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True
```

**Minimum spanning tree (Kruskal):** sort edges by weight; add an edge if it joins two different components (`union` returns true). O(E log E).

```python
edges.sort(key=lambda e: e[2])              # (u, v, w) sorted by weight
d = DSU(n)
total = 0
for u, v, w in edges:
    if d.union(u, v):
        total += w
```

(Prim: heap-based, good for dense graphs.)

**Network delay time:** Dijkstra from `k`; answer = max distance (or `-1` if some node unreachable).

**Swim in rising water:** minimize the **maximum** elevation along a path: Dijkstra with `max` as the path cost; or sort cells by elevation and union neighbors until start and end are connected (DSU); or binary search + BFS.

# Service boundaries for ML

Draw the line where **change rates and skills differ**.

- **Stable contract:** a versioned API (`POST /v1/ask`) that exposes _outcomes_, not internals: `{status: ok|no_answer, answer, citations, trace_id, model_version}`. Embedding model, index format, chunking and prompts stay behind it.
- The **gateway** doesn't import ML libraries; the **model service** doesn't do auth or rate limiting. Each deploys, scales and rolls back on its own.
- Make failure part of the contract: timeouts, `no_answer`, `429/503` with `Retry-After`, problem-details errors.
- Propagate **request/trace ids** across the boundary.
- Keep the service **stateless** (state in KV/DB/index) so it can scale horizontally and be replaced.
- Version everything the response depends on and return those versions for debugging.
