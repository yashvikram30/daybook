# The math you actually use

- **Vector:** list of numbers (a point/direction). **Dot product** `a·b = Σ aᵢbᵢ` measures alignment (0 = orthogonal); `a·b = |a||b|cosθ`.
- **Matrix × vector** applies a linear map; **matrix × matrix** composes them. Shapes: `(m×n)·(n×p) → (m×p)` (inner dims must match). A neural-net layer is `Wx + b`.
- **Derivative:** slope of `f` at a point. **Gradient** `∇L = (∂L/∂w₁, …, ∂L/∂wₙ)` points in the direction of **steepest increase** of `L`; so we step **opposite** to reduce the loss.

# Linear regression

Model `ŷ = Xw + b`. Loss (mean squared error): `L = (1/n) Σ (ŷᵢ − yᵢ)²`.
Gradients (vectorized): `∂L/∂w = (2/n) Xᵀ(ŷ − y)`, `∂L/∂b = (2/n) Σ(ŷ − y)`.
**Gradient descent:** repeat `w ← w − η ∂L/∂w`, where **η (learning rate)** sets the step size.

```python
import numpy as np
rng = np.random.default_rng(0)
x = rng.uniform(-1, 1, 200); y = 3*x + 2 + rng.normal(0, 0.3, 200)
w, b, lr = 0.0, 0.0, 0.1
for step in range(500):
    err = (w*x + b) - y
    w -= lr * 2*np.mean(err*x); b -= lr * 2*np.mean(err)
# closed form: normal equation  w = (XᵀX)⁻¹ Xᵀ y   (use np.linalg.lstsq, not an explicit inverse)
X = np.c_[x, np.ones_like(x)]; w_cf, b_cf = np.linalg.lstsq(X, y, rcond=None)[0]
```

# Learning rate behavior

| η         | Loss curve                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------- |
| too small | smooth but very slow                                                                           |
| good      | fast, then flattens                                                                            |
| too large | oscillates, or **rises / diverges (NaN)**. A rising loss means you're overshooting the minimum |

Gradient descent converges to the same answer as the normal equation for this convex problem; GD scales to huge/non-linear models where no closed form exists.

# Steps

1. Data: `y = 3x + 2 + noise` (as above). Plot the points.
2. Gradient descent loop; record `loss = mean(err**2)` each step; plot loss vs step (log y-axis helps).
3. Compare `(w, b)` to `lstsq`: they should agree to ~2-3 decimals; overlay both fitted lines on the data.
4. Learning-rate experiment: run with `lr ∈ {0.001, 0.01, 0.1, 1.0, 2.0}` (10× steps). Record steps-to-converge and what happens at the extremes; for squared loss on this data, a rate that is too large makes the loss grow geometrically. Note that **feature scale matters**: unscaled features need smaller rates.

# Graph algorithms on directed/undirected graphs

**Cycle in an undirected graph:** DFS/BFS carrying the **parent**; meeting a visited node that isn't the parent → cycle.

**Cycle in a directed graph:** DFS with three colors (white = unseen, **gray = on the current path**, black = done); an edge to a **gray** node is a cycle. Or use Kahn's algorithm: if fewer than `n` nodes get processed, a cycle exists.

**Bipartite check:** 2-color with BFS/DFS; an edge between same-colored nodes → not bipartite (equivalently: no odd cycle).

**Topological sort (DAG only), Kahn's algorithm:** repeatedly remove nodes with indegree 0.

```python
from collections import deque

def topo(n: int, adj: list[list[int]]) -> tuple[list[int], bool]:
    indeg = [0] * n
    for u in range(n):
        for v in adj[u]:
            indeg[v] += 1
    q = deque(i for i, d in enumerate(indeg) if d == 0)
    order: list[int] = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order, len(order) == n          # False -> cycle
```

(DFS alternative: postorder, then reverse.)

**Eventual safe states** (nodes from which every path ends in a terminal): nodes **not on or leading into a cycle**. Reverse all edges and run Kahn's from terminals (outdegree-0 nodes), or DFS with colors (black = safe).

All **O(V + E)**.

# Reproducible environments

"Works on my machine" is a bug. Make the environment a **file**:

- **`pyproject.toml`** declares dependencies; a **lockfile** (`uv.lock`) pins exact versions of every transitive dependency; `uv sync` recreates it. Pin the **Python version** (`.python-version`).
- Commit both files; never `pip install` ad hoc into the project environment.
- **Seed every RNG** (`random`, `numpy`, framework) and write the seed to the run log.
- System-level dependencies (CUDA, libs) → **Docker** image or documented versions.
- Record: code commit hash, data version/checksum, config, library versions.
- Test it: fresh clone → one command → same numbers.

1. **Learning rate.** The gradient only tells the _direction_ of steepest increase locally, not how far to go; η scales the step. Too big overshoots the minimum (loss rises or diverges), too small crawls. A **rising loss** usually means η is too large (or a bug in the gradient/sign).
2. **Gradient direction.** The gradient points toward the steepest **increase** of the loss; to reduce the loss we move the opposite way (`w ← w − η∇L`).
