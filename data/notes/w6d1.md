# UDP gives you almost nothing

An 8-byte header: source port, destination port, length, checksum. Datagrams may be **lost, duplicated, reordered**; message boundaries are preserved. Reliability, if you want it, is yours to build.

# Reliability toolkit

| Mechanism            | Fixes                                                 |
| -------------------- | ----------------------------------------------------- |
| Checksum / CRC       | corruption                                            |
| Sequence numbers     | duplicates, reordering, which packet an ACK refers to |
| ACKs                 | tells the sender what arrived                         |
| Retransmission timer | loss (no ACK within RTO → resend)                     |
| Window (next day)    | throughput                                            |

# Stop-and-wait

Send one packet, wait for its ACK, retransmit on timeout.

```
sender:  send(seq) ──► ... ◄── ACK(seq)   timeout? resend(seq)
receiver: if seq == expected { deliver; expected++ }  always ACK the seq it received (re-ACK duplicates)
```

Sequence numbers can be 1 bit (alternating bit) for stop-and-wait, but use wider ones in practice.

**Why it wastes bandwidth:** only one packet is in flight per RTT, so throughput ≈ packet size / RTT regardless of link speed. A 1 Gb/s link with 100 ms RTT and 1.5 KB packets carries ~120 kb/s (≈ 0.01%). The pipe holds `bandwidth × RTT` bytes (the **bandwidth-delay product**), so you need that much in flight.

# Detecting and fixing bit errors

The link layer and TCP both guard against flipped bits, with different strength:

- **Parity bit:** add one bit so the count of ones is even. It catches any single-bit error but misses any two.
- **Internet checksum** (IP, TCP, UDP): add the data as 16-bit words with ones' complement addition (carries wrap around), then invert. The receiver adds everything including the checksum; the answer must be `0xFFFF`. Cheap in software and weak against some errors. Example: words `0x6666 + 0x5555 + 0x0F0F = 0xCACA`, checksum `0x3535`.

```python
def checksum(words: list[int]) -> int:
    s = 0
    for w in words:
        s += w
        s = (s & 0xFFFF) + (s >> 16)      # wrap the carry back in
    return ~s & 0xFFFF

print(hex(checksum([0x6666, 0x5555, 0x0F0F])))   # 0x3535
```

- **CRC** (Ethernet, Wi-Fi, disks): treat the bits as a polynomial and divide by a fixed **generator**; the remainder is sent along. It is strong against bursts of errors and cheap in hardware. Example: data `1101011111`, generator `10011` (degree 4). Append four zeros, divide with XOR (no borrows) and the remainder is `0010`, so the sender transmits `1101011111 0010`. The receiver divides the whole thing and expects a remainder of zero.
- **Hamming code** corrects as well as detects. Parity bits sit at positions that are powers of two (1, 2, 4, ...) and each covers the positions whose binary index includes that bit. For the data `1011` the 7-bit codeword is `0110011`. If one bit flips, the parity checks that fail add up (1 + 2 + 4 weights) to the **position of the bad bit**, so the receiver flips it back. This **forward error correction** is used where retransmission is costly, such as memory (ECC RAM) and satellite links.

# Bandwidth-delay product

The **bandwidth-delay product** is `bandwidth × round-trip time`: how many bits are in flight when a sender keeps the pipe full. A 100 Mb/s link with a 40 ms RTT holds 500 KB. Stop-and-wait keeps only one packet in flight, so its utilisation is `packet / BDP`, tiny on long fast links. That is the argument for the sliding window next.

# Choosing the retransmission timeout (RTO)

Measure RTT samples `R` and keep smoothed estimates (Jacobson/Karels, RFC 6298):

```
SRTT   = 7/8·SRTT + 1/8·R
RTTVAR = 3/4·RTTVAR + 1/4·|SRTT − R|
RTO    = SRTT + 4·RTTVAR      (exponential backoff on each timeout)
```

**Karn's rule:** don't take RTT samples from retransmitted packets (ambiguous ACK). **Too short:** spurious retransmissions waste bandwidth and add congestion. **Too long:** slow recovery from real loss.

```python
sock.settimeout(rto)
try:
    ack, _ = sock.recvfrom(2048)
except TimeoutError:
    rto *= 2                  # exponential backoff
    resend()
```

# Lossy wrapper

```python
import random, threading

class Lossy:
    """Wraps a UDP socket; drops, delays and reorders what it sends."""

    def __init__(self, sock, drop: float = 0.0, delay: float = 0.0, jitter: float = 0.0, seed: int = 0):
        self.sock, self.drop, self.delay, self.jitter = sock, drop, delay, jitter
        self.rng = random.Random(seed)            # seeded: replay a failing run exactly

    def sendto(self, data: bytes, addr) -> int:
        if self.rng.random() < self.drop:
            return len(data)                      # silently dropped
        wait = self.delay + self.rng.uniform(0, self.jitter)    # random delay also reorders
        threading.Timer(wait, self.sock.sendto, (bytes(data), addr)).start()
        return len(data)

    def __getattr__(self, name):                  # recvfrom, settimeout, ... pass straight through
        return getattr(self.sock, name)
```

`[type u8: DATA|ACK|FIN][seq u32][len u16][crc32 u32][payload]`, built with `struct.pack(">BIHI", kind, seq, len(payload), zlib.crc32(payload)) + payload` and read back with `struct.unpack_from`.

# Stop-and-wait

Sender loop: send DATA(seq) → wait for ACK(seq) up to RTO → on timeout resend (count retries, backoff). Receiver: verify CRC, ACK, deliver only if `seq == expected`.

# Interval greedy

Most interval problems: **sort**, then sweep once.

| Problem                                  | Sort by      | Rule                                               |
| ---------------------------------------- | ------------ | -------------------------------------------------- |
| N meetings in one room (max count)       | **end** time | take a meeting if `start ≥ lastEnd`                |
| Non-overlapping intervals (min removals) | **end**      | `removals = n − maxNonOverlapping`                 |
| Merge intervals                          | **start**    | extend the last if `start ≤ last.end`, else append |
| Job sequencing (max profit)              | profit desc  | put each job in the latest free slot ≤ deadline    |

```python
iv.sort(key=lambda x: x[0])
out = [iv[0]]
for x in iv[1:]:
    last = out[-1]
    if x[0] <= last[1]:
        last[1] = max(last[1], x[1])
    else:
        out.append(x)
```

**Insert interval** (already sorted): (1) copy all intervals ending before the new one, (2) merge all overlapping into one, (3) copy the rest. O(n).

**Why sort by end** for max non-overlapping: finishing earliest leaves the most room (exchange argument).

Job sequencing: slot search is O(n·maxDeadline), or O(n log n) with a disjoint-set of free slots.

# Simulate failure in tests

Real networks fail in ways your laptop never does. Make failure a **test input**:

- Wrap I/O behind a small class or `Protocol` and inject a fake that drops, delays, duplicates, reorders, truncates or errors.
- Use a **seeded** random source so a failing run can be replayed (`random.Random(seed)`; include the seed in the assertion message so a failure shows how to replay it).
- Use a fake clock/injected timers so tests don't wait in real time.
- Assert end-to-end invariants (file checksum equal, no duplicate delivery), not packet-level details.
- Run a matrix of loss rates with `@pytest.mark.parametrize`.

1. **RTO.** Estimate RTT with a smoothed average plus variance, `RTO = SRTT + 4·RTTVAR`, back off exponentially on timeouts, and ignore samples from retransmitted packets. If too short: premature retransmissions of packets that were merely delayed, wasting bandwidth and worsening congestion.
2. **Stop-and-wait waste.** One packet per RTT is in flight, so throughput = packet size/RTT, far below capacity when `bandwidth × RTT` is large. The link sits idle while waiting for each ACK.
3. **CRC versus checksum, and parity.** A **CRC** treats the data as a polynomial and divides by a generator, so it reliably detects every **burst** error no longer than the CRC's length, and all odd numbers of bit errors with a suitable generator, and it is sensitive to the _position_ of bits. The simple Internet **checksum** is a sum, so it cannot see errors that cancel out (two words changed by opposite amounts, or words swapped, since addition does not care about order). **Parity** detects any odd number of flipped bits but **cannot detect an even number** (two flips restore the parity), and it cannot say which bit is wrong, let alone correct it.
