# Inheritance: reuse and specialise

A class can **inherit** from another, getting its attributes and methods for free and adding or changing some.

```python
class SavingsAccount(BankAccount):            # SavingsAccount "is a" BankAccount
    def __init__(self, owner, balance=0, rate=0.02):
        super().__init__(owner, balance)       # run the parent's setup
        self.rate = rate

    def add_interest(self):
        self.deposit(self.balance * self.rate)  # reuses the parent's deposit
```

`super()` reaches the parent class. A subclass can **override** a method by defining one with the same name (for example a different `withdraw` that also enforces a minimum balance). Use inheritance for a genuine "is-a" relationship. If the relationship is "has-a" (a car has an engine), put an object inside the other as an attribute; this is called **composition** and is usually simpler and more flexible.

# Polymorphism

Different classes can offer the same method, and code that uses them does not care which it has:

```python
class Circle:
    def area(self): return 3.14159 * self.r ** 2
class Square:
    def area(self): return self.side ** 2

for shape in shapes:
    print(shape.area())        # each object does its own thing
```

This "if it has the method, use it" style is called **duck typing**. `isinstance(x, BankAccount)` tests whether `x` belongs to a class or any subclass.

# Encapsulation: protect the inside

Encapsulation means keeping an object's data behind a clear interface so outside code cannot put it in a bad state. Python does not enforce secrecy; it uses conventions: a leading underscore (`_balance`) means "internal, please do not touch". A **property** lets you run code when an attribute is read or set:

```python
class Account:
    def __init__(self):
        self._balance = 0

    @property
    def balance(self):                  # read as account.balance
        return self._balance

    @balance.setter
    def balance(self, value):           # account.balance = x
        if value < 0:
            raise ValueError("negative balance")
        self._balance = value
```

Callers keep using `account.balance`, while you gain validation. You can add a property later without changing any caller, which is why Python code does not write `get_`/`set_` methods up front.

# Abstraction

Abstraction is showing _what_ something does and hiding _how_. A class's public methods are the interface; the rest is detail you can change. An **abstract base class** forces subclasses to supply the pieces:

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...
```

You cannot create a `Shape()` directly, only subclasses that define `area`. Keep hierarchies shallow: more than two levels of inheritance is usually a sign to use composition instead.
