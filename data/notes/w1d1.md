# The Computer Architecture Mental Model

Before writing code, understand what a computer actually is. A computer fundamentally consists of four interacting parts:
1. **CPU (Central Processing Unit)**: The brain that executes instructions. It contains the Arithmetic Logic Unit (ALU) for calculations, Registers for ultra-fast temporary storage, and a Control Unit that orchestrates the fetch-decode-execute cycle.
2. **RAM (Random Access Memory)**: The workspace. Think of RAM as a vast, numbered street of byte mailboxes. Each byte has an integer address (e.g., `0x1000`). When your program runs, its instructions and variables are stored here.
3. **Storage (SSD / Hard Drive)**: Permanent storage. Data stays here when the power is turned off, but reading from disk is thousands of times slower than reading from RAM.
4. **The Bus**: The high-speed wire pathways that shuttle bits between the CPU, RAM, and devices.

When you run `x = 42` in Python:
- The computer stores the value `42` at a specific memory address (which you can inspect with `id(x)`).
- The variable name `x` is simply a label pointing to that memory address.

# Python basics in one page

This is the ground the tutorial and Automate the Boring Stuff cover, in the order you will meet it.

- **Numbers:** `/` always gives a float, `//` floors, `%` is the remainder and `**` is a power. Floor division rounds toward minus infinity, so `-7 // 2` is `-4` and `-7 % 2` is `1`. The two always agree: `a == (a // b) * b + a % b`.
- **Strings** are immutable sequences of characters. `s[1:4]` is a slice (the stop index is excluded), `s[::-1]` reverses, and a slice that runs past the end does not raise. An f-string formats values in place: `f"{price:.2f}"`.
- **Indentation is the syntax.** `if`/`elif`/`else`, `while`, and `for x in iterable` all open a block with a colon and an indented body. `range(start, stop, step)` stops before `stop`. `break` leaves a loop and `continue` skips to the next pass.
- **Truthiness:** `0`, `""`, `[]`, `{}` and `None` count as false, everything else as true. Test for `None` with `is None`.
- **Functions** use `def`. A function with no `return` returns `None`. Default values are computed once, when `def` runs, so a mutable default is shared between calls:

```python
def add_item(x, items=[]):      # bug: one list for every call
    items.append(x)
    return items

def add_item(x, items=None):    # fix
    items = [] if items is None else items
    items.append(x)
    return items
```

- **Input and files:** `input()` always returns a `str`, so convert with `int(...)` or `float(...)`. `with open(path) as f:` closes the file for you, even if an error occurs.

```python
for i in range(1, 16):
    print("FizzBuzz" if i % 15 == 0 else "Fizz" if i % 3 == 0 else "Buzz" if i % 5 == 0 else i)
```

# Everything is an object

Every Python value is an object on the heap that starts with a 16-byte header: a reference count (8 bytes) and a pointer to its type (8 bytes). A variable is just a name that refers to one object, and in CPython `id(x)` is that object's address.

# Sizes on a 64-bit CPython 3.12+

| Value                         | `sys.getsizeof`   | Why                                                                                           |
| ----------------------------- | ----------------- | --------------------------------------------------------------------------------------------- |
| `0`, `1`, any int below 2**30 | 28                | 16-byte header + length + one 30-bit digit                                                    |
| `2**30`                       | 32                | a second digit: about 4 more bytes per 30 bits                                                |
| `1.5`                         | 24                | header + one 8-byte IEEE 754 `double`                                                         |
| `True`                        | 28                | `bool` is a subclass of `int`                                                                 |
| `"abc"`                       | about 41 + length | header + length, hash, flags, then the characters                                             |
| `b"abc"`                      | 33 + length       | header + length + hash + the bytes                                                            |
| `[]`                          | 56                | header + pointer to an array + length + allocated size                                        |
| `[1]`                         | 64                | 56 + room for 4 pointers is allocated at the first append, but only the used part counts here |
| `()`, `(1,)`                  | 40, 48            | header + length + 8 bytes per item pointer                                                    |

`sys.getsizeof` counts only the object itself, not the objects it refers to. A list of a million ints is a million pointers (8 MB) **plus** a million int objects (28 MB or more). That is why `array.array`, `bytes` and NumPy exist: they store raw machine values side by side.

`ctypes.sizeof(ctypes.c_int)` is 4 and `ctypes.sizeof(ctypes.c_long)` is 8 on arm64 macOS. Python's `int` is neither: it is arbitrary precision, so it grows as needed.

**Alignment and padding:** in memory, fields are aligned to their own size, so order matters. `ctypes` uses the machine's rules, so you can see them from Python.

```python
import ctypes

class A(ctypes.Structure):  # 24 bytes (7 + 7 bytes padding)
    _fields_ = [("a", ctypes.c_bool), ("b", ctypes.c_int64), ("c", ctypes.c_bool)]

class B(ctypes.Structure):  # 16 bytes
    _fields_ = [("b", ctypes.c_int64), ("a", ctypes.c_bool), ("c", ctypes.c_bool)]

print(ctypes.sizeof(A), ctypes.sizeof(B))
```

# Names, sharing and lifetime

There is no stack-or-heap choice: all objects live on the heap (small ones come from CPython's own allocator, larger ones from the system allocator). What lives on the stack is each call's **frame**, holding references. An object is freed the moment its **reference count** reaches zero; a separate cyclic collector handles objects that refer to each other.

```python
a = [1, 2]
b = a                 # no copy: two names, one list
b.append(3)
print(a, a is b)      # [1, 2, 3] True
import sys; print(sys.getrefcount(a))   # one higher than you expect: the call's own argument
```

- Small ints (-5 to 256) and many short strings are shared, so `a is b` is `True` for them. Never use `is` to compare values; use `==`.
- On 3.12+ some objects (small ints, `None`) are **immortal**: their count never changes.

Python never lets you hold a dangling reference to a Python object: a name keeps its object alive, and the object is freed only when the last name goes.

# Big-O in a nutshell

Big-O is how work grows with input size `n`, ignoring constants: `O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`. Count loops: nested loop over `n` = `O(n²)`; halving each step = `O(log n)`.

# The four sorts

| Sort      | Idea                                              | Best    | Worst   | Space | Stable |
| --------- | ------------------------------------------------- | ------- | ------- | ----- | ------ |
| Selection | pick min of the unsorted part, swap to front      | n²      | n²      | 1     | no     |
| Bubble    | swap adjacent out-of-order pairs; stop if no swap | n       | n²      | 1     | yes    |
| Insertion | insert `a[i]` into sorted prefix                  | n       | n²      | 1     | yes    |
| Merge     | split in half, sort each, merge                   | n log n | n log n | n     | yes    |

_Stable_ = equal keys keep their original order.

```python
def insertion(a: list[int]) -> None:
    for i in range(1, len(a)):
        j = i
        while j > 0 and a[j - 1] > a[j]:
            a[j - 1], a[j] = a[j], a[j - 1]
            j -= 1


def merge_sort(a: list[int]) -> list[int]:
    if len(a) <= 1:
        return a
    m = len(a) // 2
    left, right = merge_sort(a[:m]), merge_sort(a[m:])
    out: list[int] = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= keeps it stable
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    out.extend(left[i:])
    out.extend(right[j:])
    return out
```

Insertion sort is fast on nearly-sorted data, which is why real sorts use it for small chunks. Python's own `sorted` and `list.sort` use **Timsort**, which is exactly that idea: insertion sort on small runs, merge on the runs.

Slicing (`a[:m]`) copies, so this merge sort uses extra memory at every level. That is fine for learning; note it when you analyse space.

1. **Size.** A 32-bit machine integer is just 4 bytes of value. A Python `int` is an object: a 16-byte header (reference count and type pointer), a length field, and the digits. `sys.getsizeof(0)` is 28 on a 64-bit CPython 3.12+, and the number grows by about 4 bytes for every 30 more bits, because Python integers have no fixed width.
2. **Sharing.** Assignment never copies an object; it makes another name refer to the same one. Two names share an object when one was assigned from the other, or when CPython reuses a cached object (small ints, interned strings). `id(x)` is the object's address in CPython, so `is` compares addresses. Whether an object is freed is decided by its reference count reaching zero. In Python you never choose: every object lives until nothing refers to it, so there is no dangling pointer, though a reference you forget to drop can still leak memory.
