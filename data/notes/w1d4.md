# Stack frames

Each call pushes a **frame** holding: return address, saved registers, locals, spilled temporaries, outgoing args (when not in registers). The stack grows toward lower addresses on x86-64 and arm64.

```
high addr
 | caller's frame            |
 | return address (LR saved) |   <- written by prologue
 | saved frame pointer       |
 | locals / spills           |
 | ... callee frames below   |
low addr  <- sp
```

Prologue sets up the frame (`sub sp`, save LR/FP); epilogue restores and `ret`s. The **caller** (or callee, per convention) is responsible for cleanup; with a fixed frame size the callee just restores `sp`.

# Calling conventions

|              | Machine code on arm64 (AAPCS64)        | CPython (Python-level calls)                                                                     |
| ------------ | -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Int args     | `x0`-`x7`                              | none: arguments are references (pointers to objects)                                             |
| Result       | `x0` (`x1`)                            | one object reference; failure is a `NULL` result plus an exception stored on the thread          |
| Callee-saved | `x19`-`x28`                            | not applicable: the interpreter keeps its state in its own frame objects                         |
| Stack        | fixed-size, OS-set (~8 MB main thread) | each call gets a **frame** with a value stack and locals, kept in memory the interpreter manages |

A Python frame is a data structure, not a region of the machine stack. You can read it: `inspect.currentframe()` gives the current one, `f_back` the caller's, `f_locals` the locals and `f_lineno` the line.

```python
import inspect

def show():
    f = inspect.currentframe()
    while f:
        print(f.f_code.co_name, f.f_lineno, list(f.f_locals))
        f = f.f_back
```

Since Python 3.11, a call from Python code to Python code does **not** use a new machine-stack frame; the interpreter loop just switches to the new Python frame. That made calls cheaper. Python still limits recursion depth (`sys.getrecursionlimit()`, 1000 by default) and raises `RecursionError`, because runaway recursion should be an error and not a crash or an exhausted-memory machine. Recursion that passes through native code (a deeply nested `repr`, `sorted` with a key function that recurses) still uses the machine stack and can crash the process if you lift the limit too far. Without the guard, deep recursion would simply segfault at the fixed stack limit.

# Memory-safety contrast

- Machine level: a write past the end of an 8-byte stack buffer is **undefined**; it can overwrite the saved return address → control-flow hijack. Defences: stack canaries, ASLR, non-executable stack.
- Python: a list or string index is bounds-checked → `IndexError: list index out of range`. A freed object cannot be reached through a name, so use-after-free cannot happen in safe Python. `ctypes` can break all of that on purpose (`ctypes.string_at(0)` crashes the interpreter), which is exactly why the safe code is safe.

def fact(n: int) -> int:

# Deep recursion

```python
import sys

def depth(n: int) -> int:
    return 0 if n == 0 else 1 + depth(n - 1)

print(sys.getrecursionlimit())     # 1000
depth(5_000)                       # RecursionError: maximum recursion depth exceeded
sys.setrecursionlimit(200_000)
print(depth(100_000))              # how far your build goes depends on the version
```

Note the difference: Python stops you with an exception, and how far you get after raising the limit depends on the version and on memory. Without the guard the process would segfault at the 8 MB stack limit, with no message at all.

# In-place array edits

Use **two pointers** (read index, write index) to rewrite an array in O(n) time and O(1) space.

```python
# Move zeros to end (keeps order)
def move_zeroes(a: list[int]) -> None:
    w = 0
    for v in a:
        if v != 0:
            a[w] = v
            w += 1
    for i in range(w, len(a)):
        a[i] = 0


# Remove duplicates from sorted array, return new length
def dedup(a: list[int]) -> int:
    if not a:
        return 0
    w = 1
    for r in range(1, len(a)):
        if a[r] != a[w - 1]:
            a[w] = a[r]
            w += 1
    return w
```

# Rotation: reversal trick

Rotate left by `k` (`k %= n`): reverse `[0,k)`, reverse `[k,n)`, reverse all. O(n) time, O(1) space.

```python
def rotate_left(a: list[int], k: int) -> None:
    n = len(a)
    k %= n

    def rev(i: int, j: int) -> None:
        while i < j:
            a[i], a[j] = a[j], a[i]
            i, j = i + 1, j - 1

    rev(0, k - 1)
    rev(k, n - 1)
    rev(0, n - 1)
```

Rotate **right** by k = rotate left by `n-k`. Left by one: save `a[0]`, shift, put at end. The one-liner `a[:] = a[k:] + a[:k]` is also O(n) time, but it builds two temporary lists, so it is not O(1) space.

# Debug with a debugger

Print statements change timing and need a rerun each time; a debugger lets you stop and inspect everything.

| pdb command                          | Use                                             |
| ------------------------------------ | ----------------------------------------------- |
| `break file.py:42` / `break fn`      | set breakpoint                                  |
| `continue`, `next`, `step`, `return` | run / over / into / until this function returns |
| `p x`, `pp x`, `args`, `locals()`    | inspect                                         |
| `where`, `up`, `down`                | call stack, move between frames                 |
| `break 42, i == 99`                  | conditional breakpoint                          |

`python3 -m pdb script.py` starts under the debugger, `breakpoint()` stops at that line, and `pytest --pdb` drops into pdb at the first failure. Most editors drive the same machinery through debugpy.

Method: reproduce → form a hypothesis → break where it should first go wrong → check values. Write a failing test first so the bug stays fixed.

1. **Call A→B.** The caller puts args in registers (or on the stack), executes `BL`, which stores the return address in the link register. B's prologue allocates its frame (`sub sp`), saves LR/FP and any callee-saved registers it uses. On return, B restores them, deallocates and `RET`s. By convention the callee restores `sp` and its saved registers; the caller reads the result from `x0`. In CPython the same idea exists one level up: the interpreter creates a frame for B (holding its locals and value stack), runs B's bytecode, and on `RETURN_VALUE` pops that frame and hands the result back to A's frame.
2. **Overflow target.** A stack buffer sits in the frame _below_ the saved return address, and writes go to higher addresses, so a long write runs through other locals and then the return address, which the epilogue then uses to jump. Not random: it is directly adjacent. Python checks every index and raises `IndexError` instead of touching memory.
