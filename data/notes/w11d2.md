# The test pyramid

```
        ▲  few   End-to-end  (slow, brittle, whole system)
       ▲▲▲       Integration (several components, real DB/HTTP)
     ▲▲▲▲▲▲▲ many  Unit      (fast, isolated, precise failures)
```

Push each check **as low as it can go** while still testing the risk. Avoid the "ice-cream cone" (mostly slow end-to-end tests). Test **behavior through the public interface**, not implementation details, so refactors don't break tests.

# Good pytest tests

```python
import pytest

@pytest.mark.parametrize(
    ("text", "want"),
    [pytest.param("42", 42, id="ok"), pytest.param("", None, id="empty")],
)
def test_parse(text, want):
    if want is None:
        with pytest.raises(ValueError):
            parse(text)
    else:
        assert parse(text) == want

@pytest.fixture
def store(tmp_path):
    s = Store.open(tmp_path)
    yield s                       # the test runs here
    s.close()                     # cleanup runs even if the test failed
```

Pytest rewrites `assert` so a failure shows both sides and the input. **Coverage:** `pytest --cov=kvservice --cov-report=term-missing` (the pytest-cov plugin) lists the lines never executed. Coverage shows what **isn't** tested; it doesn't prove what is tested well. Run tests in parallel with `pytest -n auto` (pytest-xdist) once they are independent.

# Property-based testing and fuzzing

**Hypothesis** generates inputs (and shrinks failures to a minimal case); best for **parsers/decoders** and round trips.

```python
from hypothesis import given, strategies as st

@given(st.binary())
def test_decode_never_crashes(b):
    try:
        rec = decode(b)
    except DecodeError:
        return                                    # rejecting is fine; any other exception is a bug
    assert decode(encode(rec)) == rec             # round trip

@given(st.dictionaries(st.text(), st.binary()))
def test_encode_decode_roundtrip(d):
    assert decode(encode(d)) == d
```

Failing examples are saved in `.hypothesis/` and replayed on the next run. For coverage-guided fuzzing of Python code there is Atheris.

# Mocks

Overused mocks assert _how_ code calls collaborators, so they break on refactors and can pass while reality fails. **Prefer** real implementations or **fakes** (in-memory store, an in-process test server); **use mocks/stubs** at boundaries that are slow, nondeterministic or out of your control (third-party APIs, clocks). `unittest.mock` and pytest's `monkeypatch` make patching easy, which is also why they are overused. Wrong choice when the mock re-implements the logic under test.

# Mutation testing

A tool changes your code (`<` → `<=`, delete a line) and reruns tests; a **surviving mutant** means no test noticed. It measures test _strength_, not just coverage.

# Steps

1. Convert repetitive tests to **`parametrize` tables**; shared setup in a fixture that cleans up after the `yield`.
2. **Fuzz** the HTTP request parser (feed random bytes; property: never panics, never hangs, round-trips valid requests) and the KV record decoder (corrupt/truncated input must return an error, not panic or allocate gigabytes from a bogus length). Keep the crashing inputs as explicit `@example(...)` cases.
3. Coverage: `pytest --cov --cov-report=term-missing --cov-report=html`; open the HTML view, pick the riskiest uncovered branch (error path in recovery, compaction edge) and test it.
4. Add an **integration test**: start the server in a fixture (bind to port 0, use `tmp_path` for the store) and exercise it through HTTP with `httpx`.

# Pitfalls

- Don't assert on map iteration order or timing.
- A decoder fuzz bug is often "length field trusted": cap allocations.

# BST iterators and repair

**BST iterator** (`next`/`hasNext`, O(h) memory, amortized O(1)): keep a stack of the **left spine**; `next` pops a node, then pushes the left spine of its right child.

```python
class BSTIterator:
    def __init__(self, root: TreeNode | None) -> None:
        self.st: list[TreeNode] = []
        self._push(root)

    def _push(self, n: TreeNode | None) -> None:
        while n:
            self.st.append(n)
            n = n.left

    def next(self) -> int:
        n = self.st.pop()
        self._push(n.right)
        return n.val

    def has_next(self) -> bool:
        return bool(self.st)
```

**Two-sum in a BST:** two iterators (one ascending, one descending) as two pointers: O(n) time, O(h) space. (Or a hash set during traversal.)

**Recover a BST with two swapped nodes:** inorder should be increasing. Track `prev`; the **first** violation (`prev > cur`) gives `first = prev`; the **last** violation gives `second = cur`; swap their values.

```python
if prev and prev.val > cur.val:
    if first is None:
        first = prev
    second = cur
```

(Adjacent swap = one violation; non-adjacent = two.) Morris traversal makes it O(1) space.

**Largest BST inside a binary tree:** postorder; each call returns `(isBST, size, min, max)`. A node is a BST if both children are, `left.max < val < right.min`; size = `l + r + 1`. Track the max size. O(n).

# Mutation thinking

Ask of every test: **"if I broke the code here on purpose, would this test fail?"**

- Flip a comparison (`<` ↔ `<=`), off-by-one a boundary, return early, remove a call, swap `&&`/`||`. Do your tests notice?
- Assertions must check **outputs/effects**, not just "no error". A test that executes code without asserting gives coverage but no protection.
- Test **boundaries** (empty, one, max, max+1), **error paths** and **ordering**.
- Try it manually (edit the code, run tests, revert) or with a tool (`mutmut`, `cosmic-ray`). Every surviving mutant is a missing or weak test.
