# Supervised learning workflow

Learn a function from **labeled** examples `(x, y)` to predict `y` for **unseen** `x`. The goal is **generalization**, not low training error.

1. Split: **train** (fit), **validation** (choose models/hyperparameters), **test** (final estimate, used once).
2. **Baseline first** (predict the mean / majority class): any model must beat it.
3. Preprocess + model in a single **Pipeline** (so transforms are fit on training data only).
4. **Cross-validation** (k-fold; **stratified** for classification keeps class ratios).
5. Evaluate with the right metrics; inspect errors.

# Bias and variance

|                             | Symptom                            | Fix                                                      |
| --------------------------- | ---------------------------------- | -------------------------------------------------------- |
| **High bias (underfit)**    | poor on train _and_ validation     | more expressive model, better features                   |
| **High variance (overfit)** | great on train, poor on validation | more data, regularization, simpler model, early stopping |

# Metrics (binary)

Confusion matrix:

|              | Predicted + | Predicted − |
| ------------ | ----------- | ----------- |
| **Actual +** | TP          | FN          |
| **Actual −** | FP          | TN          |

`accuracy = (TP+TN)/all` · `precision = TP/(TP+FP)` (of the predicted positives, how many are right) · `recall = TP/(TP+FN)` (of the real positives, how many found) · `F1 = 2PR/(P+R)`. **Accuracy misleads on imbalanced data:** with 1% positives, predicting "always negative" scores 99% with zero recall. Use precision/recall, PR-AUC, and choose the threshold by the cost of FP vs FN.

# Logistic regression

`p = σ(w·x + b)`, `σ(z) = 1/(1+e⁻ᶻ)`; trained by minimizing **log loss** (cross-entropy); predict class 1 if `p ≥ threshold` (0.5 by default, adjustable).

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.dummy import DummyClassifier
from sklearn.metrics import classification_report, confusion_matrix

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
cv = StratifiedKFold(5, shuffle=True, random_state=0)
print(cross_val_score(DummyClassifier(), Xtr, ytr, cv=cv).mean(), cross_val_score(model, Xtr, ytr, cv=cv).mean())
model.fit(Xtr, ytr); print(classification_report(yte, model.predict(Xte)))   # touch the test set once
```

# Sensitivity, specificity, ROC and AUC

A classifier outputs a score; a **threshold** turns it into a yes or no. Moving the threshold trades one kind of error for the other.

- **Sensitivity** (= recall = true positive rate) = `TP / (TP + FN)`: of the real positives, how many you caught.
- **Specificity** = `TN / (TN + FP)`: of the real negatives, how many you correctly left alone. The **false positive rate** is `1 − specificity`.
- The **ROC curve** plots true positive rate against false positive rate as the threshold sweeps from high to low. A random classifier lies on the diagonal; a perfect one hugs the top-left corner.
- **AUC** is the area under that curve, and it equals the probability that a random positive scores higher than a random negative: 0.5 is chance, 1.0 is perfect. It judges the _ranking_ independent of any threshold. When positives are rare, the precision-recall curve is more informative, because ROC can look good while precision is poor.

```python
from sklearn.metrics import roc_auc_score
print(roc_auc_score(yte, model.predict_proba(Xte)[:, 1]))
```

Choose the threshold from the cost of each mistake: for a cancer screen, missing a case is worse than a false alarm, so accept lower specificity for higher sensitivity.

# Regularisation: ridge and lasso

An over-flexible model fits noise with large weights. **Regularisation** adds a penalty on the weights to the loss, so a weight must earn its size.

|                | Penalty        | Effect                                                                                                |
| -------------- | -------------- | ----------------------------------------------------------------------------------------------------- |
| **Ridge (L2)** | `λ · Σ wᵢ²`    | shrinks all weights smoothly toward zero, rarely to exactly zero; copes well with correlated features |
| **Lasso (L1)** | `λ · Σ \|wᵢ\|` | pushes some weights to exactly zero, so it also selects features                                      |
| Elastic net    | both           | a compromise                                                                                          |

`λ` (called `alpha` in scikit-learn) controls the strength: 0 is no penalty (overfits), very large flattens the model (underfits). Choose it by cross-validation, and **scale your features first** so the penalty treats them equally. In scikit-learn: `Ridge(alpha=1.0)`, `Lasso(alpha=0.1)`, or the `C` parameter of `LogisticRegression` (which is `1/λ`).

# Trees, forests and boosting

A **decision tree** repeatedly asks the yes/no question about one feature that best separates the classes, measured by how much it lowers **impurity** (Gini or entropy). It is easy to read and handles mixed features without scaling, but one deep tree memorises the training data (high variance).

- **Random forest:** train many trees, each on a random resample of the rows (**bagging**) and a random subset of features at each split, then average their votes. Averaging many different, noisy trees cancels the noise, which reduces variance, and it works well with little tuning.
- **Gradient boosting:** build trees one after another, each small and shallow, each fitted to the _errors_ the ensemble still makes (the gradient of the loss), added with a small learning rate. It reduces bias and is often the best method on tabular data (XGBoost, LightGBM, `HistGradientBoostingClassifier`). It needs more tuning and overfits if you add too many trees, so use early stopping.

```python
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
for m in (RandomForestClassifier(300, random_state=0), HistGradientBoostingClassifier()):
    print(type(m).__name__, cross_val_score(m, Xtr, ytr, cv=cv).mean())
```

# Validation vs test

Use the **validation** set (or CV) for every decision; the **test** set only at the end. Each time you pick a model _because_ of its test score, the test set leaks into your choices and the estimate becomes **optimistic**.

for a, b in zip(words, words[1:]):

# Data leakage as a bug class

**Leakage** = information from outside the training data (or not available at prediction time) influences training or evaluation, so scores look great and production fails.

| Kind           | Example                                                                          | Defence                                     |
| -------------- | -------------------------------------------------------------------------------- | ------------------------------------------- |
| Preprocessing  | scaler/imputer/PCA fit on all data before splitting                              | **Pipeline**; fit only on train folds       |
| Target leakage | feature derived from the label (e.g. `discharge_status` predicting `readmitted`) | ask "would I have this at prediction time?" |
| Temporal       | random split on time-ordered data (train sees the future)                        | split by time, `TimeSeriesSplit`            |
| Group          | same patient/user/document in train and test                                     | `GroupKFold`                                |
| Duplicates     | near-identical rows across splits                                                | dedupe before splitting                     |
| Selection      | tuning on the test set                                                           | test used once                              |

**Smell:** results that are too good to be true. Investigate feature importances and suspiciously strong single features.

1. **Validation vs test.** Validation data guides decisions (model choice, hyperparameters, thresholds); the test set gives one final unbiased estimate. Reusing the test set to choose means the model is partly fit to it, so the reported score is optimistic.
2. **Accuracy on imbalance.** A model that always predicts the majority class gets high accuracy while finding none of the minority cases. Use precision, recall, F1/PR-AUC and the confusion matrix.
3. **Forest versus tree.** A single deep decision tree memorises the training data: it has **low bias but high variance**, so small changes in the data produce a very different tree. A random forest trains many trees on bootstrap samples with random feature subsets, so they make different, partly independent errors, and **averaging** their votes cancels much of the noise. The result keeps low bias while greatly reducing variance, so it generalises better, usually with little tuning, at the cost of interpretability and speed.
4. **L1 versus L2.** Both shrink weights by penalising their size. **L2** (ridge) penalises squared weights, shrinking all of them smoothly but rarely to exactly zero. **L1** (lasso) penalises absolute values, whose sharp corner at zero drives some weights to **exactly zero**, which removes those features and so acts as automatic feature selection.
