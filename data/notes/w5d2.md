# What TCP provides

A **reliable, ordered, flow-controlled, congestion-controlled byte stream** on top of unreliable IP, using: sequence numbers, cumulative ACKs, retransmission on timeout/duplicate ACKs, checksums, a receive **window** (flow control) and congestion control (week 6).

# Handshake and teardown

```
client                       server
  | --- SYN, seq=x --------->  |   (LISTEN -> SYN_RCVD)
  | <-- SYN+ACK, seq=y, ack=x+1|
  | --- ACK, ack=y+1 -------->  |   ESTABLISHED
  ...data...
  | --- FIN ---------------->  |   active closer: FIN_WAIT_1
  | <-- ACK ----------------   |   (server may still send: half-close)
  | <-- FIN ----------------   |
  | --- ACK ---------------->  |   active closer enters TIME_WAIT
```

SYN and FIN each consume one sequence number. Why 3-way: both sides must learn each other's initial sequence number and confirm reachability.

# The TCP header and TCP versus UDP

| Field                       | Size         | Purpose                                                         |
| --------------------------- | ------------ | --------------------------------------------------------------- |
| Source and destination port | 16 bits each | which process on each host                                      |
| Sequence number             | 32 bits      | position in the byte stream of the first data byte              |
| Acknowledgement number      | 32 bits      | the next byte the sender of this segment expects                |
| Data offset                 | 4 bits       | header length in 32-bit words (minimum 5, so 20 bytes)          |
| Flags                       | 6+ bits      | `SYN`, `ACK`, `FIN`, `RST`, `PSH`, `URG`                        |
| Window                      | 16 bits      | how much more data the receiver can buffer (flow control)       |
| Checksum                    | 16 bits      | over the header, data and a pseudo-header with the IP addresses |
| Options                     | variable     | MSS, window scaling, SACK, timestamps                           |

|            | TCP                                                          | UDP                                                             |
| ---------- | ------------------------------------------------------------ | --------------------------------------------------------------- |
| Connection | yes: handshake first                                         | none                                                            |
| Delivery   | reliable, ordered byte stream                                | best effort, separate datagrams                                 |
| Controls   | flow and congestion control                                  | none                                                            |
| Header     | 20+ bytes                                                    | 8 bytes                                                         |
| Use        | web, email, file transfer, anything where every byte matters | DNS, video calls, games, QUIC: low delay beats perfect delivery |

TCP has **no message boundaries**: ten `send()` calls may arrive as one `recv()`, or one as ten. That is why your protocols need a length prefix or a delimiter.

# States to know

| State                              | Meaning                                        |
| ---------------------------------- | ---------------------------------------------- |
| LISTEN / SYN_RCVD / ESTABLISHED    | server socket, half-open, connected            |
| FIN_WAIT_1/2, CLOSE_WAIT, LAST_ACK | teardown steps                                 |
| **TIME_WAIT**                      | **active closer** waits 2×MSL (~60 s on Linux) |

**TIME_WAIT:** the side that sends the first FIN waits so that (a) its final ACK can be retransmitted if lost, and (b) delayed old segments from this connection die out before the same 4-tuple is reused. Many short connections closed by the _server_ pile up TIME_WAIT there.

# Half-close and failure

- `sock.shutdown(socket.SHUT_WR)` sends FIN but you can still read: "I'm done sending."

```python
sock.shutdown(socket.SHUT_WR)       # half-close; keep calling recv() until it returns b""
```

- **Peer crashes without FIN:** nothing arrives. Data in flight is lost; your writes keep being retransmitted with backoff until a timeout (minutes) or an RST arrives (after the peer reboots). A blocked `recv` waits **forever** unless you set a **timeout** (`sock.settimeout(10)`, or `asyncio.timeout` around the read) or enable TCP keepalive (`sock.setsockopt(socket.SOL_SOCKET, socket.SO_KEEPALIVE, 1)`; the interval options are platform-specific).

```python
try:
    data = conn.recv(4096)
except TimeoutError:        # socket.timeout is an alias of TimeoutError since Python 3.10
    conn.close()            # idle: drop it
```

# 2D matrices

**Search in a fully sorted matrix** (each row sorted, first of row > last of previous): treat as a 1D array of length `m*n`; `mid → (mid // n, mid % n)`. O(log mn).

**Rows sorted and columns sorted (matrix II):** staircase from the **top-right**: if `x == cur` found; `cur > x` → left; `cur < x` → down. O(m+n).

```python
r, c = 0, n - 1
while r < m and c >= 0:
    v = mat[r][c]
    if v == x:
        return True
    if v > x:
        c -= 1
    else:
        r += 1
return False
```

**Peak in 2D:** binary search over **columns**: take the column `mid`, find the row `r` of its max; compare with left/right neighbors; go toward the greater one. O(m log n).

**Matrix median** (row-wise sorted, odd count): binary search the **value** `x` in `[min, max]`; `count(x) = Σ upper_bound(row, x)`; find the smallest `x` with `count(x) > (m*n)/2`. O(m log n log range).

# Timeouts everywhere

Any network call can hang forever. Python's `socket.socket()` **blocks forever by default** (no timeout), and many libraries pass that through, so a slow or malicious client can hold connections and threads indefinitely (slowloris). Libraries that do set a default are the exception: with `requests`, for example, the default is _no timeout_ unless you pass one.

```python
import asyncio, socket

sock = socket.create_connection(("example.com", 80), timeout=5)    # connect timeout
sock.settimeout(10)                                                  # every later read and write

async def fetch(reader: asyncio.StreamReader) -> bytes:
    async with asyncio.timeout(2):            # one overall deadline for this block
        return await reader.readline()
```

For a server, set an idle timeout per connection, a limit on header size and on the number of connections, and a deadline for the whole request. In `http.server`, `timeout = 10` on the handler class sets the socket timeout.

Rules: set a timeout on every outbound call, propagate deadlines, and make the budget shrink down the call chain.

1. **TIME_WAIT.** After the TCP close handshake, the side that closed **first** (active closer) keeps the connection state for ~2×MSL to retransmit a lost final ACK and to let stray old segments expire so they can't corrupt a new connection with the same addresses/ports. The passive side already got the final ACK, so it can close immediately.
2. **Crash without FIN.** No signal arrives: the sender's data goes unacknowledged and is retransmitted with exponential backoff until the connection times out (or an RST comes if the host reboots). A reader blocks indefinitely unless a read deadline or keepalive notices. Anything in flight or unacknowledged is lost.
