# A project gets its own environment

Different projects need different packages and versions. A **virtual environment** is a private folder of Python packages for one project, so installing something for one never breaks another.

```
uv init myproject           # or: python3 -m venv .venv
cd myproject
uv add requests             # or: .venv/bin/pip install requests
uv run python main.py       # or activate with: source .venv/bin/activate
```

`uv` (used in the main course) creates the environment, records dependencies in `pyproject.toml` and runs your code inside it. Never install packages into the system Python. Commit `pyproject.toml` and the lock file but not the `.venv` folder (list it in `.gitignore`).

Fetching a web page shows packages at work:

```python
import requests
r = requests.get("https://example.com")
print(r.status_code, r.text[:80])
```

# Testing with pytest

A test is a small function that checks your code and fails loudly if it is wrong. With `pytest`, name the file `test_something.py`, name functions `test_...`, and use a plain `assert`:

```python
from grades import letter_grade

def test_normal():
    assert letter_grade(85) == "B"

def test_top_edge():
    assert letter_grade(100) == "A"

def test_bad_score():
    import pytest
    with pytest.raises(ValueError):
        letter_grade(-5)
```

Run `uv run pytest`. A passing run tells you a change did not break old behaviour; a failing one points at the exact case. Test the normal case, the edges and the invalid input. Writing the test first, watching it fail, then making it pass is a habit worth building.

# Git: a history you can go back to

Git records snapshots of your project so you can see what changed, undo mistakes and work on an idea without risking the working version.

```
git init                          # start tracking this folder
git status                        # what changed
git add main.py                   # choose what goes in the next snapshot
git commit -m "Add grade function"  # take the snapshot, with a message saying why
git log --oneline                 # the history
git switch -c experiment          # a new branch to try something
git switch main && git merge experiment    # bring it back
```

Commit small and often, with a message that explains the change. A **branch** is a separate line of work; **merge** combines it back. GitHub or another host stores a copy online (`git push`). Keep secrets and generated files out with `.gitignore`.

# The command line, briefly

You will use a terminal every day: `pwd`, `ls`, `cd`, `mkdir`, `cat file` (show a file), `rm file` (delete, and there is no undo), `python3 script.py`. Tab completes names and the up arrow repeats the previous command. If a command prints nothing and returns, it usually worked.
