# Evaluate retrieval and answers separately

End-to-end "is the answer good?" can't tell you **which stage failed**.

| Stage      | Failure                                                             | Metric                                      |
| ---------- | ------------------------------------------------------------------- | ------------------------------------------- |
| Retrieval  | right chunk not retrieved/ranked low                                | recall@k, MRR, nDCG                         |
| Generation | chunk retrieved but ignored, misread or contradicted; hallucination | correctness, **faithfulness**               |
| Abstention | answers an unanswerable question, or refuses an answerable one      | correct-abstention rate, false-refusal rate |

If retrieval recall@5 is 60%, no prompt will push answer accuracy above ~60% on those questions: fix retrieval first.

# Retrieval metrics

- **Recall@k / hit rate:** fraction of questions with at least one gold chunk in the top `k` (or the fraction of all gold chunks found).
- **MRR:** mean of `1/rank` of the first relevant result. **nDCG@k:** graded relevance with a position discount. **Precision@k:** fraction of the top `k` that's relevant.

```python
def hit_at_k(ranked, gold, k): return bool(set(ranked[:k]) & gold)
def rr(ranked, gold):
    return next((1 / i for i, d in enumerate(ranked, 1) if d in gold), 0.0)
mrr = sum(rr(r, g) for r, g in runs) / len(runs)
```

# Answer metrics (Ragas names)

**Context precision/recall** (retrieval), **faithfulness** (every claim is supported by the retrieved context), **answer relevancy**, **correctness** vs a reference answer. Use **code checks** where possible (citation ids present, required facts via string/regex) and an **LLM judge** with a rubric elsewhere (and validate the judge).

# Failure points (Barnett et al.)

Missing content in the corpus · right doc not in top-k · relevant doc dropped when building the prompt · answer in context but **not extracted** · wrong format · wrong specificity · incomplete answer.

# Ablations

Change **one thing at a time** on the **same** golden set: chunk size, hybrid on/off, reranker on/off, contextual chunks on/off. Report a table of metric deltas, plus cost and latency.

# BEIR

Retrievers that win on one dataset can lose on another (BM25 is a surprisingly strong baseline out of domain): **evaluate on your own data**.

# Metrics script

- Retrieval: hit@5, MRR over answerable questions (use the retriever output **before** generation).
- Answers: correctness (judge vs `reference`), faithfulness (judge: each claim supported by the retrieved text), **correct abstention** (unanswerable → `no_answer`) and **false refusal** (answerable → `no_answer`).

# Partition and interval DP (more)

**Palindrome partitioning II** (min cuts): precompute `isPal[i][j]` (expand around centres or DP), then `dp[i]` = min cuts for `s[:i]` with `dp[0] = -1` (so a whole-prefix palindrome costs `-1 + 1 = 0` cuts):

```python
dp = [0] * (n + 1)
dp[0] = -1
for i in range(1, n + 1):
    dp[i] = i - 1                                  # worst case: cut between every char
    for j in range(i):
        if is_pal[j][i - 1]:
            dp[i] = min(dp[i], dp[j] + 1)
return dp[n]
```

**Partition array for maximum sum** (split into subarrays of length ≤ k; each becomes its max value): `dp[i] = max over len=1..k of dp[i-len] + len·max(a[i-len..i-1])`.

**Minimum cost to cut a stick:** add `0` and `n` to the sorted cuts; `dp[i][j] = min_k dp[i][k] + dp[k][j] + (cuts[j] − cuts[i])` for `k` strictly between `i` and `j` (the **last** cut made in this segment).

**Different ways to evaluate a boolean expression:** interval DP over operands; for each operator `k` split, combine counts of `true`/`false` of left and right according to `&`, `|`, `^`.

| Pattern             | Complexity                      |
| ------------------- | ------------------------------- |
| prefix partition DP | O(n²) (O(nk) with a length cap) |
| interval DP         | O(n³)                           |

# Small samples and false wins

With **40 questions**, one question = **2.5 percentage points**. A system that scores 80% (32/40) has a 95% confidence interval of roughly **±12 points** (`1.96·√(0.8·0.2/40) ≈ 0.12`). A "5-point win" is **two questions**: noise.

- **Look at flips:** which questions went right → wrong and wrong → right (**paired** comparison on the same questions). A significance test for paired binary outcomes: **McNemar's test**; or bootstrap the difference.
- Report **confidence intervals**, not just point values; prefer more questions over more metrics.
- **Fix the sample size and the stopping rule in advance** and don't peek until done (Evan Miller's "how not to run an A/B test").
- **Multiple comparisons:** try 20 variants and one will "win" by chance; treat the best-of-many with suspicion and confirm on a fresh set.
- **Keep a held-out set**; if you tuned on the whole golden set, the final number is optimistic.
- A real effect shows up consistently across metrics, slices and fresh data.

1. **Separate retrieval and answer.** Retrieval sets the ceiling (the model can't use a chunk it never saw); measuring them separately tells you which stage to fix and prevents blaming the prompt for a retrieval miss (or the retriever for a generation mistake).
2. **Golden-set leakage.** Warning signs: scores keep rising on the golden set but fresh questions don't improve; you copied golden questions into few-shot examples or tuned chunk size/prompt by repeatedly looking at them; gold labels were derived from your retriever's output. Defence: hold out questions until the end and write new ones for the final check.
3. **Largest improvement.** _Your table decides._ Answer with the delta, the number of questions that flipped, and a confidence interval; with 40 questions, differences under ~10 points are weak evidence.
