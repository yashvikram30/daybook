# Delivery semantics

| Semantics               | How                                                                                         | Failure             |
| ----------------------- | ------------------------------------------------------------------------------------------- | ------------------- |
| At-most-once            | send once, no retry                                                                         | message may be lost |
| **At-least-once**       | retry until acked                                                                           | **duplicates**      |
| Exactly-once delivery   | **impossible** in general (Two Generals: you can't know whether an unacked message arrived) |                     |
| **Exactly-once effect** | at-least-once delivery + **idempotent / deduplicated processing**                           |                     |

A timeout tells you nothing about whether the server **did** the operation. So retries are needed, and retries need **idempotency**.

# Idempotency

An operation is idempotent if repeating it has the same effect as doing it once (`PUT /x` = set, `DELETE`; **not** `POST /charge`, `balance += 10`).

**Idempotency key** (Stripe): the client generates a unique key per _logical_ operation (UUID) and sends it with every retry; the server stores `key → result` **atomically with the effect** and returns the stored result for repeats.

```python
def handle(self, key: str, op: Op) -> Result:
    if key in self.results:
        return self.results[key]            # duplicate: same answer, no re-execution
    r = self.apply(op)
    self.results[key] = r                   # in one atomic step (same transaction/log entry)
    return r
```

Keys expire after some window; in a Raft KV store, record `(clientID, seq) → result` **in the replicated state machine**, so a retry to a new leader is still deduplicated.

# Atomic commit across nodes: two-phase commit

When one transaction touches data on several nodes, they must all commit or all abort. **Two-phase commit** (2PC) uses a **coordinator**:

1. **Prepare (voting):** the coordinator asks every participant "can you commit?" Each participant durably logs its answer; a "yes" is a promise that it can commit no matter what happens next.
2. **Commit (decision):** if everyone voted yes, the coordinator logs _commit_ and tells all; if anyone voted no or timed out, it logs _abort_ and tells all.

Its weakness is **blocking**: if the coordinator crashes after participants voted yes but before they hear the decision, they cannot decide alone, and they hold their locks until it returns. Consensus-based commit (a replicated coordinator, as in Spanner) removes the single point of failure. Compare with the idempotent, retry-based **saga** pattern: do each step locally and undo with a compensating action if a later step fails, trading isolation for availability.

# Retries: backoff and jitter

Fixed immediate retries from many clients become a **retry storm**: they hit the recovering server simultaneously, in synchronized waves, and keep it down. Use **exponential backoff** (`base · 2^attempt`, capped) with **full jitter** (`sleep = random(0, backoff)`) to spread load; cap attempts; retry only idempotent/safe operations; respect `Retry-After`; use **retry budgets**.

```python
import random

def backoff(attempt: int, base: float = 0.1, cap: float = 10.0) -> float:
    return random.uniform(0, min(cap, base * 2**attempt))        # full jitter
```

# Circuit breaker

States: **closed** (normal) → **open** after N consecutive failures (fail fast, no calls) → **half-open** after a cool-down (let a trial request through; success closes, failure re-opens). Protects both the caller (no waiting on timeouts) and the struggling dependency.

# Messaging (Kafka-style log)

Producers append to a partitioned, durable log; consumers track their **offset**. Delivery is at-least-once unless consumers dedupe (or use transactions/idempotent producers).

# Kafka consumer groups

A topic is split into **partitions**; each is an ordered, append-only log with numbered **offsets**. Order is guaranteed only within a partition, so messages that must stay in order share a key (the key picks the partition). A **consumer group** shares the work: each partition is read by exactly one consumer of the group, so adding consumers scales reading up to the number of partitions. Consumers **commit their offset** after processing; if one dies, its partitions move to another, which resumes from the last committed offset, so anything processed but not yet committed is processed twice. That is at-least-once delivery again, and why handlers must be idempotent.

# API in front of the Raft KV

- `PUT /kv/{key}` with header `Idempotency-Key: <uuid>`; body = value. Handler proposes a command `{key, value, idem_key}` to the leader.
- State machine: `if idem_key in seen: return seen[idem_key]`; otherwise apply the command and store `seen[idem_key] = res`. `seen` is part of the **replicated** state (and snapshot). Generate keys with `str(uuid.uuid4())`.
- Not leader → `307`/`503` with a leader hint; clients retry.

# Client

```python
import time
import httpx

def put_with_retries(client: httpx.Client, url: str, body: bytes, key: str, attempts: int = 5) -> httpx.Response:
    last: Exception | None = None
    for attempt in range(attempts):
        try:
            r = client.put(url, content=body, headers={"Idempotency-Key": key}, timeout=2.0)   # per-try timeout
            if r.status_code < 500:
                return r
        except httpx.TransportError as e:                                                     # timeouts, resets
            last = e
        time.sleep(backoff(attempt))
    raise RuntimeError("gave up") from last
```

Reuse **the same** `Idempotency-Key` across retries of one logical write.

# Construction, serialization, Morris

**Serialize/deserialize (preorder with null markers):**

```python
def ser(n: TreeNode | None, out: list[str]) -> None:
    if n is None:
        out.append("#")
        return
    out.append(str(n.val))
    ser(n.left, out)
    ser(n.right, out)

def deser(tokens: "Iterator[str]") -> TreeNode | None:
    t = next(tokens)
    if t == "#":
        return None
    return TreeNode(int(t), deser(tokens), deser(tokens))     # left is built before right: argument order is evaluation order

# usage: out = []; ser(root, out); s = ",".join(out); root2 = deser(iter(s.split(",")))
```

(Level-order with nulls also works; the preorder form is shorter.)

**Build from postorder + inorder:** last postorder element is the root; build the **right** subtree first when consuming postorder from the end (or split by sizes).

**Morris traversal: O(1) extra space** by temporarily threading the tree: link each node's **inorder predecessor's** right pointer to the node.

```python
cur = root
while cur:
    if cur.left is None:
        visit(cur)
        cur = cur.right
        continue
    pre = cur.left
    while pre.right and pre.right is not cur:
        pre = pre.right
    if pre.right is None:
        pre.right = cur                    # make thread (preorder: visit(cur) HERE)
        cur = cur.left
    else:
        pre.right = None                   # remove thread (inorder: visit HERE)
        visit(cur)
        cur = cur.right
```

Inorder visits when **returning** via the thread; preorder visits when **first arriving** (before going left). Each edge is traversed at most twice: O(n) time, O(1) space, but it mutates the tree temporarily (not thread-safe).

# Resilience patterns

| Pattern                             | Purpose                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------- |
| **Timeout**                         | bound waiting; every remote call needs one                                |
| **Retry + backoff + jitter**        | survive transient faults (idempotent ops only)                            |
| **Circuit breaker**                 | stop hammering a failing dependency                                       |
| **Bulkhead**                        | isolate resources (separate pools/queues per dependency)                  |
| **Rate limiting / load shedding**   | protect yourself under overload                                           |
| **Fallback / graceful degradation** | return cached or partial results                                          |
| **Hedged requests**                 | send a second request after a delay to cut tail latency (idempotent only) |

Combine carefully: **retries multiply load** (3 layers × 3 tries = 27×), so retry at **one** layer and use budgets. Always **observe**: count retries, breaker state and timeouts as metrics.

1. **Exactly-once.** A sender can't distinguish "message lost" from "ack lost" (Two Generals), so it must retry (at-least-once). Exactly-once effects come from making the receiver **idempotent** (idempotency keys / deduplication stored atomically with the effect).
2. **No jitter.** Clients that failed at the same moment back off by identical delays and retry in synchronized bursts, overloading the recovering server again (thundering herd / retry storm). Jitter desynchronizes them.
3. **Two-phase commit blocking.** After participants vote _yes_ in the prepare phase they have promised to commit and must hold their locks until they learn the decision. If the **coordinator crashes** before sending it, they cannot decide alone (the coordinator may have decided either way), so they are stuck holding locks until it recovers. A **replicated coordinator**, its decision log kept by a consensus group such as Raft or Paxos, survives the loss of one node: another replica takes over and finishes the protocol, so participants are no longer waiting on a single machine.
