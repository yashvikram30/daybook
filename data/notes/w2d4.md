# Pipelining

Split an instruction into stages (classic 5: **IF** fetch, **ID** decode, **EX** execute, **MEM**, **WB** write-back) so a new instruction starts each cycle. Throughput ≈ 1 instruction/cycle even though each takes 5.

```
cycle:   1  2  3  4  5  6
I1:      IF ID EX ME WB
I2:         IF ID EX ME WB
I3:            IF ID EX ME WB
```

# Hazards

| Hazard     | Cause                               | Remedy                                    |
| ---------- | ----------------------------------- | ----------------------------------------- |
| Structural | two instructions need the same unit | duplicate hardware                        |
| Data       | I2 needs I1's result                | forwarding, stall, out-of-order execution |
| Control    | branch outcome unknown              | **branch prediction**, speculation        |

A **mispredicted branch** flushes everything fetched after it. The cost is about the pipeline depth (15-20+ cycles on deep pipelines), so deeper pipelines make mispredictions pricier.

# Modern CPUs

Superscalar (several instructions per cycle), **out-of-order** execution (run whichever instruction has its inputs ready, retire in order), register renaming, speculative execution, caches. Spectre-style bugs come from speculation leaving cache traces.

# Interrupts and I/O

- **Polling:** CPU loops reading a status register. Simple, wastes cycles, adds latency.
- **Interrupt:** device raises a signal; CPU finishes the current instruction, saves state, jumps to a handler via a vector table, then returns. Efficient for rare events.
- **DMA** lets devices copy to memory without the CPU.

```python
# One keypress without waiting for Enter, using the standard library
import sys, termios, tty

fd = sys.stdin.fileno()
old = termios.tcgetattr(fd)
try:
    tty.setcbreak(fd)            # per-key input; Ctrl-C still works
    ch = sys.stdin.read(1)
finally:
    termios.tcsetattr(fd, termios.TCSADRAIN, old)   # always restore the terminal
```

3. Timer: keep a `next_tick` time and add `1/60` each frame, sleeping for `next_tick - time.monotonic()`; decrement delay/sound on each tick. Run CPU at ~500-700 instr/sec (several steps per tick). Sleeping a fixed `1/60` instead drifts, because the work in between takes time too.
4. Note on pipeline hazards: your emulator executes one instruction at a time, so no hazards; a pipelined design would need forwarding for `Vx` reads right after writes, and branch handling for `1NNN`/`2NNN`/skips.

# Matrix tricks

**Rotate 90° clockwise, in place:** transpose, then reverse each row. O(n²) time, O(1) space. (Counter-clockwise: transpose, reverse each column / reverse rows first.)

```python
n = len(m)
for i in range(n):
    for j in range(i + 1, n):
        m[i][j], m[j][i] = m[j][i], m[i][j]
for row in m:
    row.reverse()
```

**Set matrix zeroes in O(1) space:** use the first row and first column as marker flags.

1. Remember whether row 0 / col 0 contain a zero (two bools).
2. For every `m[i][j]==0` (i,j≥1) set `m[i][0]=m[0][j]=0`.
3. Zero cells (i,j≥1) whose row or column marker is 0.
4. Finally zero row 0 / col 0 if flagged.

**Pascal's triangle variants:** row n (1-indexed) is `C(n-1, k)`; element at row r, column c is `C(r-1, c-1)`. Build a whole row iteratively: `x = x * (n-i) / i`.

```python
def row(n: int) -> list[int]:
    r, x = [1], 1
    for i in range(1, n):
        x = x * (n - i) // i
        r.append(x)
    return r
```

# Tag and release

A **tag** names a commit permanently; releases are tags plus notes.

```
git tag -a v1.0.0 -m "First release"
git push origin v1.0.0
```

**Semantic Versioning** `MAJOR.MINOR.PATCH`:

| Bump  | When                        |
| ----- | --------------------------- |
| MAJOR | incompatible API change     |
| MINOR | backward-compatible feature |
| PATCH | backward-compatible fix     |

Python packages put the version in `pyproject.toml` (`version = "1.0.0"`), following PEP 440, which accepts `MAJOR.MINOR.PATCH` and adds pre-releases such as `1.0.0rc1`. Tag the commit `vX.Y.Z` to match, build with `uv build`, and publish with `uv publish` if it is meant for others. Keep a `CHANGELOG`.

1. **Misprediction cost.** The pipeline has already fetched and started executing instructions along the wrong path. Detecting the error happens late (at EX/resolve), and all those in-flight instructions must be flushed and fetch restarted from the correct target. The deeper the pipeline, the more stages of wasted work (~15-20 cycles).
2. **Polling vs interrupt.** Polling: the program repeatedly asks the device "any key?", burning cycles and adding latency up to one poll period. Interrupt: the device signals the CPU, which pauses the program, runs a handler, then resumes: no wasted checks, immediate response, but needs state saving and handler infrastructure.
