# The hierarchy (order of magnitude)

| Level     | Size               | Latency           |
| --------- | ------------------ | ----------------- |
| Registers | ~1 KB              | ~0.3 ns (1 cycle) |
| L1 cache  | 32-128 KB / core   | ~1 ns (~4 cycles) |
| L2 cache  | 0.25-16 MB         | ~3-5 ns           |
| L3 cache  | tens of MB, shared | ~10-40 ns         |
| DRAM      | GBs                | ~60-100 ns        |
| SSD       | TBs                | ~10-100 µs        |

Each level is smaller, faster and costlier per byte than the next. Programs run fast when they hit the top levels.

# Locality

- **Temporal:** reuse recently used data (stays in cache).
- **Spatial:** use data next to what you just used. Memory moves in **cache lines** (64 B on most x86; 128 B on Apple M-series). Touching one byte loads the whole line.

```python
# fast: sequential, 1 miss per line          # slow: stride = row length, ~1 miss per access
a.sum(axis=1)   # sums each row of a C-ordered NumPy array    vs    a.sum(axis=0) on a Fortran-ordered one
```

An `array.array` or NumPy array is contiguous raw memory. A Python `list` is contiguous too, but it holds **pointers**, and the ints or objects it points to can be anywhere; a **linked list** of Python objects scatters nodes, so each hop is a likely cache miss and the CPU cannot prefetch. Both are O(n), but constants differ 10-100×. For plain Python code the interpreter's own overhead often hides the cache effect, which is why these experiments use NumPy or `array`.

# Cache organization

Address splits into **tag | set index | block offset**. Direct-mapped: 1 line per set; N-way set associative: N lines per set; conflict misses occur when many addresses map to the same set (e.g. power-of-two strides). Misses: _compulsory_ (first touch), _capacity_ (working set too big), _conflict_.

# False sharing

Two cores write **different variables on the same cache line**. The coherence protocol (MESI) keeps invalidating the line between cores, so threads slow each other down though they share no data. Fix: pad/align hot per-thread data to a cache line.

# PEP 8 in a nutshell

PEP 8 is the community style guide. You do not have to memorise it, because `ruff format` applies most of it, but you should be able to read it:

- 4 spaces per indent level, never tabs mixed in; lines up to about 88 characters (ruff's default).
- `snake_case` for functions, variables and modules; `PascalCase` for classes; `UPPER_SNAKE_CASE` for constants; a leading underscore (`_helper`) means "internal".
- Imports at the top, one per line, in three groups separated by a blank line: standard library, third-party, your own.
- Two blank lines between top-level definitions, one between methods. Spaces around operators (`a + b`) but not inside brackets or before a call's parenthesis.
- Compare to `None` with `is`, not `==`. Prefer `if items:` over `if len(items) > 0:`. Never use a bare `except:`.
- Comments explain **why**, not what the line already says. A docstring on every public function says what it does and what it returns.

Consistency beats personal taste: when a project has its own rules, follow them.

# Experiments

1. **Row vs column:** `N=4096`, `m = np.zeros((N, N), dtype=np.int32)`; sum along each row (`m.sum(axis=1)`) vs along each column of the same array (`m.sum(axis=0)`), then repeat with `np.asfortranarray(m)`. Expect the two orderings to differ by a visible factor, and to swap when the layout changes. Print `m.strides` to see why.
2. **Stride:** `a = np.zeros(1 << 27, dtype=np.int32)`; time `a[::stride] += 1` for strides 1, 2, 4... 1024, and divide by the number of elements touched. Time per access is flat while the stride is below a cache line, then rises (each access is a new line), then may drop when the access count falls.
3. **Knees:** compare plot knees (array size sweep) to `sysctl hw.l1dcachesize hw.l2cachesize hw.cachelinesize`.
4. **List vs array:** build a 1M-node linked list of Python objects in _shuffled_ allocation order, a `list` of 1M ints and an `array.array("i")` of the same values. Sum each. The array wins clearly; work out how much of the gap is the interpreter and how much is memory.

# Tips

- Use `min(timeit.repeat(...))`, not a single run, and keep other programs quiet.
- Keep setup out of the timed statement; run each size several times and look at the spread.
- Use `time.perf_counter_ns()` when you time by hand.

# Patterns

**Missing number in 0..n** (or 1..n): `expected - actual` with `n(n+1)/2`, or XOR all indices and values (no overflow risk with fixed-width integers; Python ints cannot overflow, but the XOR trick is still O(1) space).

```python
def missing(a: list[int]) -> int:
    x = len(a)
    for i, v in enumerate(a):
        x ^= i ^ v
    return x
```

**Two pointers on sorted arrays** (union / intersection / merge): O(n+m).

```python
def intersect(a: list[int], b: list[int]) -> list[int]:
    out: list[int] = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] < b[j]:
            i += 1
        elif a[i] > b[j]:
            j += 1
        else:
            out.append(a[i])
            i += 1
            j += 1
    return out
```

Union: same walk, append the smaller (skip if equal to last appended).

**Majority element (> n/2): Boyer-Moore voting**, O(n) time, O(1) space.

```python
cand, cnt = 0, 0
for v in a:
    if cnt == 0:
        cand = v
    cnt += 1 if v == cand else -1
```

If a majority is not guaranteed, do a second pass to verify `cand`.

# Profiling mindset

**Measure, then optimize; never guess.** Most time is in a few hot spots.

```
python3 -m cProfile -o prof.out script.py
python3 -m pstats prof.out            # then: sort cumtime, stats 20
py-spy record -o flame.svg -- python3 script.py     # flame graph of a running program
```

| Profile       | Answers                                                       |
| ------------- | ------------------------------------------------------------- |
| `cProfile`    | which functions take the time, and how often they are called  |
| `tracemalloc` | which lines allocate memory, and how much                     |
| `py-spy`      | where a running process is spending time, without changing it |

Workflow: benchmark baseline → profile → change one thing → re-benchmark. Keep the change only if the numbers (not intuition) improve.

1. **List vs array.** Same O(n) operation count, but an array is contiguous: each cache line fetch serves several elements and the hardware prefetcher predicts the stride. Linked-list nodes sit anywhere; every `next` pointer is a dependent load that likely misses cache and cannot be prefetched, costing ~DRAM latency each.
2. **False sharing.** Cores cache memory in lines (64 B). If two threads write different variables that share one line, the coherence protocol bounces ownership of the line between cores on every write, causing misses and stalls. Cause: the line, not the variable, is the unit of coherence. Fix by padding.
