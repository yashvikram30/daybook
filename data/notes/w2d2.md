# Virtual Memory: The Grand Illusion

If multiple programs run simultaneously, how do they not corrupt each other's data? And what if two programs both want address `0x1000`?
Virtual Memory gives each program its own private illusion of an entire, contiguous memory universe starting from 0. The addresses your code sees are **virtual addresses**, and hardware (the MMU) transparently translates them to physical RAM frames.

# Why virtual memory

Each process gets its own **virtual address space**; the CPU's MMU translates virtual → physical using **page tables** the OS maintains. Benefits: isolation, simple linking/loading, demand paging, memory-mapped files, copy-on-write, overcommit.

```
virtual addr = [ VPN | offset ]  --page table-->  [ PFN | offset ] = physical addr
```

Pages are 4 KiB on x86-64 (Linux); Apple silicon macOS uses 16 KiB.

# Page tables and the TLB

x86-64 uses 4 levels (9 bits each + 12 offset = 48-bit VA); a walk costs up to 4 memory reads. The **TLB** caches recent translations (hit ≈ 1 cycle); a miss triggers a walk. Context switch to another process must switch/flush the TLB (or use ASIDs/PCIDs).

# Page fault, step by step

1. Instruction accesses a virtual address; MMU finds the PTE not present (or permission violation).
2. CPU traps to the kernel's fault handler, saving the faulting PC.
3. Kernel checks the address is valid for a region (VMA). If not → `SIGSEGV`.
4. **Minor fault:** page is in memory (e.g. first touch of anonymous memory → zero-filled frame, or in page cache) → map it. **Major fault:** read from disk/swap first.
5. Update PTE, return from exception; the CPU **re-executes the same instruction**, which now succeeds.

# Page replacement

When physical memory is full and a page fault needs a frame, the OS must evict a page. A **replacement policy** picks the victim. Count **page faults** on a reference string to compare policies.

| Policy      | Evicts                                   | Notes                                                             |
| ----------- | ---------------------------------------- | ----------------------------------------------------------------- |
| **FIFO**    | the page that has been in memory longest | simple, but ignores use; can evict a hot page                     |
| **Optimal** | the page not needed for the longest time | the lower bound; needs the future, so it is only a yardstick      |
| **LRU**     | the page unused for the longest time     | approximates optimal using the past; needs per-access bookkeeping |
| **Clock**   | first page whose reference bit is 0      | cheap LRU approximation: a hand sweeps, clearing bits as it goes  |

The textbook string `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1` with 3 frames gives **15** faults for FIFO, **12** for LRU and **9** for optimal.

**Belady's anomaly:** under FIFO, more frames can mean more faults. The string `1 2 3 4 1 2 5 1 2 3 4 5` gives 9 faults with 3 frames but 10 with 4. LRU and optimal never do this, because their resident set with `n` frames is always a subset of the set with `n + 1` (the "stack property").

```python
def faults(refs: list[int], frames: int, policy: str) -> int:
    mem: list[int] = []          # front = next victim for FIFO and LRU
    misses = 0
    for i, page in enumerate(refs):
        if page in mem:
            if policy == "lru":
                mem.remove(page)
                mem.append(page)  # most recently used goes to the back
            continue
        misses += 1
        if len(mem) == frames:
            if policy == "opt":   # evict the page used furthest in the future
                def next_use(p: int) -> int:
                    return refs.index(p, i + 1) if p in refs[i + 1:] else len(refs)
                mem.remove(max(mem, key=next_use))
            else:
                mem.pop(0)
        mem.append(page)
    return misses
```

Real systems use **clock** or a related approximation, because tracking exact recency on every memory access is too costly. A dirty page costs a disk write on eviction, so many kernels prefer clean victims.

# Address-space layout (typical)

```
high  | stack (grows down)      |
      | mmap region, libs       |
      | heap (grows up / mmap)  |
      | .data / .bss            |
low   | .text (code)            |
```

CPython gets memory from the OS with `mmap` (its object arenas) and `malloc`. It never moves an object once allocated, so `id(x)` stays the same for the object's whole lifetime. Compare that with runtimes whose garbage collectors relocate objects.

# Errors are exceptions

A failed system call surfaces as an `OSError` (or one of its subclasses such as `FileNotFoundError` and `PermissionError`), with the system's `errno` value attached.

```python
import errno, mmap

try:
    m = mmap.mmap(-1, 1 << 30)                 # anonymous, private, read-write
except OSError as e:
    if e.errno == errno.ENOMEM:
        ...                                    # handle the case you know about
    raise RuntimeError("could not map 1 GiB") from e   # `from e` keeps the original as __cause__
```

Catch the narrowest exception you can handle, let the rest propagate, and use `raise ... from err` so a traceback shows both. Use `with` (a context manager) so cleanup runs whether or not an exception happens: `with mmap.mmap(-1, n) as m: ...`.

# Patterns

**Leaders:** scan from the right keeping `max` so far; an element is a leader if it exceeds everything to its right. O(n).

```python
def leaders(a: list[int]) -> list[int]:
    out: list[int] = []
    mx = float("-inf")
    for v in reversed(a):
        if v > mx:
            out.append(v)
            mx = v
    out.reverse()
    return out
```

**Rearrange by sign (equal counts, keep order):** write positives to even indices, negatives to odd, in a new list. O(n) time and space.

```python
res = [0] * len(a)
p, n = 0, 1
for v in a:
    if v > 0:
        res[p] = v
        p += 2
    else:
        res[n] = v
        n += 2
```

**Spiral matrix:** four shrinking boundaries `top, bottom, left, right`; after the top and right passes, re-check `top<=bottom` / `left<=right` before the reverse passes.

**Pascal's triangle:** `row[j] = prev[j-1] + prev[j]`, or a single entry via `C(n,k) = C(n,k-1)·(n-k+1)/k`.

```python
def n_cr(n: int, r: int) -> int:
    res = 1
    for i in range(r):
        res = res * (n - i) // (i + 1)
    return res
```

Integer division is exact at every step. The standard library has `math.comb(n, r)`; write your own first, then check it against that.

1. **Page fault.** Instruction touches a virtual page whose PTE is not present → MMU raises an exception → kernel handler saves state, finds the VMA covering the address (else SIGSEGV), allocates/loads a frame (zero-fill, from file/page cache, or from swap), updates the page table, then returns to the _same_ instruction, which now succeeds.
2. **Same address, different contents.** Each process has its own page table, so identical virtual addresses map to different physical frames (isolation). The same VA in two processes is only coincidentally equal.
3. **FIFO, LRU and clock.** FIFO evicts by arrival time and ignores use, so with more frames the set of resident pages is not always a superset of the smaller case; the string `1 2 3 4 1 2 5 1 2 3 4 5` gives 9 faults with 3 frames and 10 with 4 (**Belady's anomaly**). LRU and optimal have the **stack property**: the pages held with `n` frames are always a subset of those held with `n + 1`, so more memory never hurts. **Clock** approximates LRU cheaply: pages sit in a circle with a reference bit, the hand clears bits as it sweeps and evicts the first page whose bit is already 0 (it was not used since the last sweep). **Thrashing** is when the processes' working sets do not fit in memory, so most references fault and the CPU waits on the disk; the cure is fewer processes, more memory, or a smaller working set.
