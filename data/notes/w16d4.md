# Strongly connected components and cut structure

**Most stones removed (same row or column):** stones in the same row/column are connected; remove all but one per **component** → answer = `stones − components`. Use DSU on **row ids and column ids** (e.g. union `x` with `y + 10001`).

**Kosaraju's algorithm (SCCs in a directed graph), O(V+E):**

1. DFS the graph; push each node on a stack **when it finishes**.
2. **Transpose** the graph (reverse all edges).
3. Pop nodes from the stack; DFS in the **transposed** graph from each unvisited node; each DFS tree is one SCC.

**Bridges (Tarjan) and articulation points:** DFS with `tin[u]` (discovery time) and `low[u]` (lowest `tin` reachable via the subtree plus one back edge).

```python
timer = 0
tin = [0] * n
low = [0] * n
bridges: list[tuple[int, int]] = []
is_art = [False] * n

def dfs(u: int, parent: int) -> None:
    global timer
    timer += 1
    tin[u] = low[u] = timer
    children = 0
    for v in adj[u]:
        if v == parent:
            continue
        if tin[v]:                                          # back edge
            low[u] = min(low[u], tin[v])
            continue
        dfs(v, u)
        children += 1
        low[u] = min(low[u], low[v])
        if low[v] > tin[u]:
            bridges.append((u, v))                          # bridge
        if parent != -1 and low[v] >= tin[u]:
            is_art[u] = True                                # articulation point
    if parent == -1 and children > 1:
        is_art[u] = True                                    # root rule
```

- **Bridge** `(u,v)`: removing it disconnects the graph ⇔ `low[v] > tin[u]`.
- **Articulation point** `u`: non-root with a child `v` where `low[v] ≥ tin[u]`; the root needs **≥ 2** DFS children.
  (For multi-edges skip the parent by **edge id**, not vertex.)

# Write the retrospective

A retrospective turns experience into learning. Keep it short and honest.

1. **What I set out to do / what I built.**
2. **What went well** (keep doing).
3. **What didn't / what was harder than expected** (why?).
4. **What I learned** (concepts and habits, with an example each).
5. **What I still don't understand** (specific questions).
6. **Next steps:** 2-3 concrete projects or readings with a first action each and a date.

Habits worth keeping: commit small, test first, measure before optimizing, write things down, review code, state guarantees, design for failure.
