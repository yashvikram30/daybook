# Sliding window

Allow up to **W unacknowledged packets in flight**. Throughput ≈ `W × packet / RTT`, so the pipe is full when `W ≥ bandwidth × RTT`.

| Scheme           | Receiver                                                              | On loss                            |
| ---------------- | --------------------------------------------------------------------- | ---------------------------------- |
| Go-Back-N        | accepts only in-order; **cumulative ACK**                             | resend from the lost packet onward |
| Selective Repeat | buffers out-of-order, ACKs each                                       | resend only the lost one           |
| TCP              | cumulative ACK **+ SACK**; fast retransmit after **3 duplicate ACKs** | resend missing segments            |

```
sender: base ─────────── nextSeq ──────── base+W
        [acked][ in flight, unacked ][ may send ][ not yet ]
```

A cumulative `ACK(n)` means "everything below `n` received" and slides `base` to `n`.

**Window size limits.** With `k`-bit sequence numbers there are 2ᵏ distinct numbers. Go-Back-N can use a window of up to 2ᵏ − 1; selective repeat only 2ᵏ⁻¹, because with a larger window the receiver cannot tell a retransmission from a new packet that reuses the number. The best throughput is reached when the window covers the bandwidth-delay product; stop-and-wait is simply a window of 1.

# Flow vs congestion control

- **Flow control:** don't overrun the _receiver_: advertised window `rwnd`.
- **Congestion control:** don't overrun the _network_: sender-computed `cwnd`.
- Sender may have `min(cwnd, rwnd)` bytes in flight.

# Congestion control (Reno-style)

```
cwnd
 │        loss             ssthresh = cwnd/2
 │      ╱╲   ╱╲   (AIMD sawtooth: +1 MSS per RTT, ÷2 on loss)
 │ slow╱  ╲╱  ╲╱
 │start (exponential: cwnd doubles each RTT until ssthresh)
 └──────────────────────────────── time
```

- **Slow start:** cwnd += 1 MSS per ACK → doubles per RTT (initial window ~10 MSS).
- **Congestion avoidance (AIMD):** +1 MSS per RTT; on loss detected by 3 dup ACKs: `ssthresh = cwnd/2`, `cwnd = ssthresh` (fast recovery); on **timeout**: `cwnd = 1 MSS`, back to slow start.
- **Why halve but grow slowly:** overshoot causes queue overflow/collapse (costly), under-use is merely slower; AIMD also converges to a **fair** share among flows.
- Modern variants: **CUBIC** (Linux default), **BBR** (models bandwidth and RTT instead of reacting to loss).

# Bufferbloat

Oversized router buffers + loss-based congestion control: flows keep filling the buffer until it overflows, so queues stay full and add **hundreds of ms of delay**. Interactive traffic (video calls, games, SSH) sharing the queue suffers. Fix: smaller buffers and active queue management (CoDel/fq_codel), BBR.

# Sliding window sender

State: `base`, `next`, `window: dict[int, bytes]` (sequence number → packet), one timer for `base`. Send while `next < base+W`. On `ACK(n)`: delete `[base,n)`, set `base = n`, reset the timer. On timeout: resend from `base` (Go-Back-N) or just the oldest unacked.

# Congestion control

```python
if cwnd < ssthresh:
    cwnd += 1                 # per ACK in slow start
else:
    cwnd += 1 / cwnd          # additive increase (in packets)
# loss (timeout):     ssthresh = max(cwnd / 2, 2); cwnd = 1
# loss (3 dup ACKs):  ssthresh = max(cwnd / 2, 2); cwnd = ssthresh
w = min(int(cwnd), rwnd)
```

Log `(time, cwnd)` each ACK to CSV; plot with matplotlib, gnuplot or a spreadsheet at 1%, 5%, 10% loss. Expect the sawtooth, and a lower average window as loss rises (throughput ∝ `1/√p`).

# Greedy, harder

**Minimum platforms / groups:** sort arrivals and departures separately; sweep with two pointers: arrival → `cur++`, departure → `cur--`; answer = max `cur`. (Or a min-heap of end times.)

**Valid parenthesis string** (with the wildcard `*`): track the possible range `[lo, hi]` of unmatched `(`.

```python
lo = hi = 0
for c in s:
    if c == "(":
        lo += 1
        hi += 1
    elif c == ")":
        lo -= 1
        hi -= 1
    else:                         # "*" may be "(", ")" or empty
        lo -= 1
        hi += 1
    if hi < 0:
        return False
    lo = max(lo, 0)
return lo == 0
```

**Candy** (higher rating than neighbour gets more): two passes.

```python
c = [1] * n
for i in range(1, n):
    if r[i] > r[i - 1]:
        c[i] = c[i - 1] + 1
for i in range(n - 2, -1, -1):
    if r[i] > r[i + 1]:
        c[i] = max(c[i], c[i + 1] + 1)
```

**Jump Game II** (min jumps): BFS by levels without a queue.

```python
jumps = end = far = 0
for i in range(len(a) - 1):
    far = max(far, i + a[i])
    if i == end:
        jumps += 1
        end = far
```

All O(n) (or O(n log n) with the sort).

# Benchmark properly

- Isolate **one** variable; same machine, same inputs, quiet system.
- Warm up; keep setup out of the timed code (`timeit`'s `setup=`, or pytest-benchmark's `pedantic` mode with a setup function); keep results used so nothing is optimised away.
- Repeat (`timeit.repeat`, or pytest-benchmark's automatic rounds) and compare distributions (min, median, standard deviation), not single numbers. `pytest --benchmark-compare` compares against a saved run.
- Report time per operation and memory (`tracemalloc`); vary input size (`parametrize`) to see **curves**.
- For network code, control the environment (loss, RTT, bandwidth) and say what it was.

```python
import pytest

@pytest.mark.parametrize("size", [64, 1024, 16384])
def test_send(benchmark, size):
    payload = bytes(size)
    benchmark(send, payload)          # runs send(payload) many times and records the timings
```

1. **Halve and +1.** Loss signals the network is overloaded; a multiplicative cut backs off quickly to relieve it, while a gentle additive increase probes for spare capacity carefully (overshooting is expensive). AIMD also drives competing flows toward equal shares.
2. **Go-Back-N versus selective repeat, and the window limit.** When one packet is lost, Go-Back-N resends it **and every packet after it**, even those that arrived correctly, so it wastes the most on a long path with a large window or a lossy link; selective repeat resends only the lost one, at the price of receiver buffering and per-packet timers. The window for selective repeat must be at most **half** the sequence space: with a larger one, after a lost ACK the sender may retransmit packet `k` while the receiver's new window already expects a new packet with the same sequence number `k`, so the receiver cannot tell an old retransmission from new data. (Go-Back-N's receiver only accepts in order, so a window of 2ᵏ − 1 is safe.)
3. **Bufferbloat.** Deep buffers plus loss-based congestion control let queues fill completely before any loss signals congestion, so every packet waits behind a long queue. Throughput is fine but latency rises to hundreds of ms, which ruins interactive traffic.
