# Self-attention

Each token produces a **query**, **key** and **value** via learned projections of its embedding: `Q = XW_Q`, `K = XW_K`, `V = XW_V`. A token's output is a **weighted average of all values**, weights = how well its query matches each key:

`Attention(Q, K, V) = softmax(Q Kᵀ / √d_k) · V`

| Tensor                     | Shape (T tokens)          |
| -------------------------- | ------------------------- |
| X                          | T × d_model               |
| Q, K                       | T × d_k                   |
| scores = QKᵀ/√d_k          | **T × T**                 |
| weights (row-wise softmax) | T × T, each row sums to 1 |
| output = weights·V         | T × d_v                   |

**Why divide by √d_k:** dot products of d_k-dimensional vectors have variance ∝ d_k; large scores push softmax into saturation (near one-hot, tiny gradients). Scaling keeps variance ≈ 1.

# Multi-head attention

Run `h` heads in parallel, each with `d_k = d_model/h`, then concatenate and project with `W_O`. Different heads can attend to different relations (position, syntax, copying).

# Causal mask

For language modeling, token `i` may only see tokens `≤ i`: set scores for `j > i` to `−∞` before softmax (upper triangle). **Training** processes all positions in one parallel pass, so without the mask position `t` could just read the answer at `t+1`; at **inference** future tokens don't exist yet, so nothing needs hiding (the mask is just what makes the two consistent).

# Position information

Attention is **permutation-equivariant**: shuffle the tokens and the outputs shuffle identically, so without positions the model sees a bag of words ("dog bites man" = "man bites dog"). Add **positional encodings** (sinusoidal, learned, or rotary/RoPE).

# Quadratic cost

Scores are `T×T`: compute `O(T²·d)` and memory `O(T²)` per head, so doubling context ≈ 4× attention cost. This limits context length; mitigations: FlashAttention (computes exactly without materializing T×T), sliding-window/sparse attention, KV caching at inference.

# A decoder block (pre-LayerNorm)

```
x = x + MultiHeadAttention(LN(x))
x = x + MLP(LN(x))            # MLP: d → 4d → d with GELU
```

**Parameters per block ≈ 12·d²** (attention `4d²` for W_Q, W_K, W_V, W_O; MLP `8d²`). Check: GPT-2 small, d=768, 12 layers: `12·12·768² ≈ 85M` + embeddings `50,257·768 ≈ 39M` ≈ **124M** ✓.

```python
import numpy as np
def attention(Q, K, V, mask=None):
    scores = Q @ K.swapaxes(-1, -2) / np.sqrt(Q.shape[-1])    # (..., T, T)
    if mask is not None: scores = np.where(mask, scores, -1e9)
    w = np.exp(scores - scores.max(-1, keepdims=True)); w /= w.sum(-1, keepdims=True)
    return w @ V
mask = np.tril(np.ones((T, T), dtype=bool))                    # lower-triangular = allowed
```

# Dynamic programming: the recipe

DP = recursion with **overlapping subproblems** + **optimal substructure**, computed once each.

1. **State:** what does `dp[i]` mean? 2. **Recurrence:** how does it depend on smaller states? 3. **Base cases.** 4. **Order** (small → large). 5. **Answer** location. Then **space-optimize** (keep only the last few states).

Three styles: **memoized recursion** (top-down), **tabulation** (bottom-up), **rolling variables**.

| Problem                                 | State and recurrence                                                  |
| --------------------------------------- | --------------------------------------------------------------------- |
| Climbing stairs                         | `dp[i] = dp[i-1] + dp[i-2]` (Fibonacci)                               |
| Frog jump (min energy)                  | `dp[i] = min(dp[i-1] + abs(h[i]-h[i-1]), dp[i-2] + abs(h[i]-h[i-2]))` |
| Frog jump, up to K                      | `dp[i] = min over j in 1..K of dp[i-j] + abs(h[i]-h[i-j])`            |
| Max sum, no two adjacent / House robber | `dp[i] = max(dp[i-1], dp[i-2] + a[i])` (skip or take)                 |

```python
def rob(a: list[int]) -> int:
    prev2 = prev1 = 0                 # best up to i-2, up to i-1
    for v in a:
        prev2, prev1 = prev1, max(prev1, prev2 + v)
    return prev1

def climb(n: int) -> int:
    a, b = 1, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

Take-or-skip is the pattern behind most 1D DP. Time O(n) (O(nK) for frog-K), space O(1) after optimization.

1. **Quadratic cost.** Every token attends to every other, giving a `T×T` score matrix: compute and memory grow with `T²`. It limits context length (and makes long prompts expensive), motivating FlashAttention, windowed/sparse attention and KV caching.
