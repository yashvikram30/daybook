# Finishing one real project

You have now seen every building block. The final project is practice at the harder skill: taking a vague goal to a finished program. Choose the budget app, Copy Special or Log Puzzle, and work in this order.

1. **Read the whole specification** before writing any code, and list the inputs, the outputs and three example cases with exact results.
2. **Sketch the pieces**: which data structure holds the information (a list? a dictionary of lists?), and which functions you need, each with one job and a docstring.
3. **Build and test in thin slices.** Make the simplest version that works end to end (even if it handles only one case), run it, and then add the next feature. Commit after each working step.
4. **Test the edges and the bad inputs** (empty, zero, huge, wrong type). Turn the checks you run by hand into two or three `pytest` tests.
5. **Clean up**: good names, no dead code, no repeated blocks, sensible error messages.
6. **Write a README**: what it does, how to run it, an example of its output, and what you would improve.

A short README template:

```
# Project name
One sentence on what it does.

## Run it
uv run python main.py input.txt

## Example
(paste a short run)

## Notes
What was hard, what you would do next.
```

# Are you ready for week 1?

The main course assumes you can do the following **without looking anything up**:

- write `FizzBuzz` (loops, `%`, `if/elif/else`);
- read a text file and count word frequencies with a dictionary;
- write a function with a default argument and a docstring, and say what it returns;
- write a small class with `__init__`, an attribute, and two methods;
- read a traceback and name the kind of error;
- run a script, install a package into a virtual environment, and commit with git.

If one of these is shaky, repeat that day's practice rather than pushing on, because weeks 1 and 2 revise exactly this ground in a new setting (memory, bytes and the machine). You do not need to know everything in the Python library; you need to be comfortable being stuck, reading an error, and working it out. That skill is what the next sixteen weeks build on.

# Where this leads

Week 1 of the main plan starts by looking _under_ what you have just used: what a variable really is in memory, how an integer is stored, what a function call does to the stack. Everything here keeps working, but you will now understand why.
