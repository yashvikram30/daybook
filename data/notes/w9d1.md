# What makes it hard: partial failure

On one machine things mostly work or the whole thing crashes. In a distributed system **some parts fail while others keep running**, and you can't always tell which.

# Fault model

| Layer   | Failures                                                                                                                      |
| ------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Nodes   | **crash-stop** (halts), **crash-recovery** (restarts, keeps disk), pauses (GC, VM stall), **Byzantine** (arbitrary/malicious) |
| Network | message **loss, delay, duplication, reordering, partition**                                                                   |
| Time    | clocks drift/skew, jump; no global clock                                                                                      |

Timing models: _synchronous_ (known bounds), _partially synchronous_ (bounds hold eventually; what real protocols assume), _asynchronous_ (no bounds).

# Fallacies of distributed computing

The network is reliable · latency is zero · bandwidth is infinite · the network is secure · topology doesn't change · there is one administrator · transport cost is zero · the network is homogeneous.

# Two Generals

Two armies must attack together, messengers can be captured. Whatever message is last can be lost, so **no finite exchange gives certainty** that both agreed. Real systems accept this: use **timeouts, retries, acknowledgements, idempotent operations** (so a retry is safe), and protocols (consensus, 2PC with recovery) that guarantee safety under stated assumptions rather than certainty.

# Crashed vs slow

**You can't tell** in an asynchronous network: silence could be a crash, a long GC pause, a lost packet or a partition. A **failure detector** (heartbeats + timeout; or phi-accrual) only _suspects_, and can be wrong. Short timeouts → false positives; long → slow recovery. Protocols must stay _safe_ even when suspicion is wrong (e.g. a deposed leader keeps running briefly).

# faultnet

```python
import asyncio, random

class Net:
    def __init__(self, n: int, drop: float = 0.0, dup: float = 0.0, delay: float = 0.01, seed: int = 0) -> None:
        self.inbox = [asyncio.Queue() for _ in range(n)]
        self.drop, self.dup, self.delay = drop, dup, delay
        self.cut: set[tuple[int, int]] = set()            # (from, to) pairs that cannot talk
        self.rng = random.Random(seed)                    # seeded, so a failing run replays

    def _jitter(self) -> float:
        return self.delay * (0.5 + self.rng.random())

    def send(self, src: int, dst: int, msg) -> None:
        if (src, dst) in self.cut or self.rng.random() < self.drop:
            return
        loop = asyncio.get_running_loop()
        loop.call_later(self._jitter(), self.inbox[dst].put_nowait, msg)       # delay (also reorders)
        if self.rng.random() < self.dup:
            loop.call_later(self._jitter(), self.inbox[dst].put_nowait, msg)   # duplicate

    def partition(self, a: list[int], b: list[int]) -> None:
        self.cut |= {(i, j) for i in a for j in b} | {(j, i) for i in a for j in b}

    def heal(self) -> None:
        self.cut.clear()
```

Everything runs on one event loop, so no locks are needed, and nodes are `asyncio` tasks that `await net.inbox[me].get()`.

# Tree basics

```python
from dataclasses import dataclass

@dataclass
class TreeNode:
    val: int
    left: "TreeNode | None" = None
    right: "TreeNode | None" = None
```

Recursion shape: handle `None`, then combine results from `left` and `right`.

| Traversal   | Order        | Use                                  |
| ----------- | ------------ | ------------------------------------ |
| Preorder    | node, L, R   | copy a tree, serialize               |
| Inorder     | L, node, R   | **sorted order in a BST**            |
| Postorder   | L, R, node   | delete a tree, compute from children |
| Level order | BFS by depth | shortest/levels                      |

```python
from collections import deque

def inorder(n: TreeNode | None, out: list[int]) -> None:
    if n is None:
        return
    inorder(n.left, out)
    out.append(n.val)
    inorder(n.right, out)

# iterative inorder
st, cur = [], root
while cur or st:
    while cur:
        st.append(cur)
        cur = cur.left
    cur = st.pop()
    out.append(cur.val)
    cur = cur.right

# level order
res, q = [], deque([root])
while q:
    level = []
    for _ in range(len(q)):
        n = q.popleft()
        level.append(n.val)
        if n.left:
            q.append(n.left)
        if n.right:
            q.append(n.right)
    res.append(level)
```

Python's recursion limit (about 1000) means a recursive traversal of a very deep (skewed) tree raises `RecursionError`; the iterative versions do not.

**All three orders in one pass:** stack of `(node, state)`; state 1 → push left (preorder visit), 2 → inorder visit, push right, 3 → postorder visit.

All are O(n) time; recursion uses O(height) space (O(n) worst case, O(log n) balanced).

# Design for failure

Assume every dependency will be slow, down or wrong.

- **Timeouts** on every call; **retries with exponential backoff + jitter**, only for idempotent operations, with a cap (retry storms amplify outages).
- **Circuit breaker:** stop calling a failing dependency for a while; **bulkheads:** isolate resource pools so one failure can't exhaust everything.
- **Graceful degradation:** serve stale cache, drop optional features, **load shed** under overload.
- **Redundancy:** no single point of failure; health checks and failover.
- Make operations **idempotent**; use request ids.
- Test failure paths (fault injection), not just the happy path.

```python
import random

def backoff(attempt: int, base: float = 0.1, cap: float = 10.0) -> float:
    return random.uniform(0, min(cap, base * 2**attempt))      # exponential backoff with full jitter
```
