# The training pipeline

| Stage                              | Data                                                                   | Objective                                | Result                                                                |
| ---------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------- |
| **Pretraining**                    | trillions of tokens of web/books/code                                  | predict the next token (self-supervised) | **base model**: broad knowledge and language, but just continues text |
| **Supervised fine-tuning (SFT)**   | thousands-millions of (prompt → ideal response) pairs                  | next-token loss on the responses         | follows instructions and formats; chat style                          |
| **Preference tuning (RLHF / DPO)** | pairs of responses with a human/AI **preference** (chosen vs rejected) | make preferred answers more likely       | helpfulness, safety, tone; fewer bad behaviors                        |

Pretraining is by far the most expensive; the later stages are cheap and shape _behavior_ more than _knowledge_.

**RLHF:** train a **reward model** on preferences, then optimize the model with RL (PPO) against it, with a **KL penalty** to stay near the SFT model. **DPO** skips the reward model and RL loop: a classification-style loss directly raises the log-probability ratio of the chosen over the rejected response (relative to a frozen reference model).

# LoRA (parameter-efficient fine-tuning)

Freeze the pretrained weight `W (d×k)` and learn a **low-rank update**: `W' = W + (α/r)·B·A`, with `B (d×r)`, `A (r×k)`, rank `r` ≈ 4-64.

- Trainable parameters per matrix: `r(d+k)` instead of `d·k` (typically **< 1%** of the model).
- Needs far less memory (no optimizer state for the frozen weights); adapters are small files; can be **merged** into `W` for zero extra inference cost, or swapped per task. **QLoRA** = LoRA on a 4-bit quantized base.

```python
from peft import LoraConfig, get_peft_model
cfg = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"], lora_dropout=0.05, task_type="CAUSAL_LM")
model = get_peft_model(base_model, cfg)
model.print_trainable_parameters()      # e.g. trainable params: 0.4M || all params: 500M || 0.08%
```

# Prompting vs retrieval vs fine-tuning

| Need                                                                                                 | Use                                                                  |
| ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| quick behavior change                                                                                | **prompting** (instructions, few-shot): cheapest, try first          |
| **new or changing facts**, private/large corpora, citations                                          | **retrieval (RAG)**: update an index, not weights; traceable sources |
| **style, format, tone**, narrow repeatable task, consistent structured output, smaller/cheaper model | **fine-tuning**                                                      |

Fine-tuning is poor at reliably adding _knowledge_ (it can hallucinate it) and goes stale; retrieval is poor at changing _behavior/format_. They combine.

# Held-out data

Once you've looked at the held-out set to make decisions (prompt wording, hyperparameters, example selection, "fixing" labels), it has influenced the model: it's no longer an unbiased estimate; use a fresh set for the final number.

# DP: stock problems as a state machine

Model each day's **state** (holding / not holding, transactions used) and transitions.

| Problem                        | Idea                                                             |
| ------------------------------ | ---------------------------------------------------------------- |
| Buy & sell I (one transaction) | track `minPrice`; `best = max(best, p − minPrice)`               |
| II (unlimited)                 | sum of all positive daily differences                            |
| With fee                       | `hold = max(hold, free − p)`; `free = max(free, hold + p − fee)` |
| With cooldown                  | states hold / sold / rest                                        |
| III (≤ 2 transactions)         | four states: `buy1, sell1, buy2, sell2`                          |
| IV (≤ k)                       | `dp[t][day]`, or `buy[t]`/`sell[t]` arrays                       |

```python
# II with fee, O(1) space
free, hold = 0, -prices[0]
for p in prices[1:]:
    free, hold = max(free, hold + p - fee), max(hold, free - p)
return free

# III: at most two transactions
b1, s1, b2, s2 = -prices[0], 0, -prices[0], 0
for p in prices[1:]:
    b1 = max(b1, -p)
    s1 = max(s1, b1 + p)
    b2 = max(b2, s1 - p)
    s2 = max(s2, b2 + p)
return s2
```

**Cherry pickup II** (two robots start at the top corners, move down one row each step to `col−1/col/col+1`): state `dp[row][c1][c2]` = best from row downward; 9 transitions per state; add cherries once if `c1 == c2`. Time O(rows·cols²·9).

# Treat training data like code

Data determines behavior as much as code does, so give it the same discipline.

- **Version it** (Hugging Face Datasets revisions, DVC, or hash + manifest); record which version trained which model.
- **Review changes**: diffs on examples, PRs for edits, a changelog.
- **Test it**: schema validation, no duplicates/near-duplicates, label balance, length limits, no PII/secrets, train/eval **no overlap**.
- **Split before looking**; freeze the held-out set; never edit it to make a score look better.
- Record **provenance and license** of each source; keep a **datasheet** (what, how collected, known gaps).
- Make the pipeline **reproducible** (scripts, seeds), not manual edits.

```python
from datasets import load_dataset
ds = load_dataset("json", data_files={"train": "train.jsonl", "test": "heldout.jsonl"})
assert not set(ds["train"]["prompt"]) & set(ds["test"]["prompt"])      # no leakage
```

1. **Stages.** Pretraining gives general knowledge and language ability (next-token prediction). SFT teaches the model to follow instructions and formats. Preference tuning shapes which of several acceptable answers it prefers (helpfulness, safety, tone).
2. **Retrieval over fine-tuning.** When knowledge changes often, is large/private, needs citations or must be updatable/deletable without retraining. Fine-tune for behavior/format; retrieve for facts.
