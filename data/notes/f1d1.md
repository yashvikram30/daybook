# What a program is, and what Python does with it

A **program** is a list of instructions written in a language the computer can be made to follow. You write it as plain text in a file (a **script**, usually ending in `.py`). **Python** is both the language and the program that reads it: the **interpreter** reads your file from the top, one instruction at a time, and does what each says.

There are two ways to use it:

- **The shell (REPL).** Type `python3` in a terminal and you get a `>>>` prompt. Each line you type runs at once and shows its result. Use it to try things out. Leave with `exit()`.
- **A script.** Save lines in a file such as `hello.py` and run `python3 hello.py`. Use this for anything you want to keep or run again.

```python
# hello.py: a line starting with # is a comment; Python ignores it
print("Hello, world")
print("2 + 3 =", 2 + 3)
```

`print()` shows something on the screen. What you put between the brackets is its **argument**. Text goes in quotes, and numbers do not need them. Arguments are separated by commas, and `print` puts a space between them.

# The terminal in four commands

You will start Python from a terminal, so learn the few commands that matter: `pwd` (where am I), `ls` (what is here; `dir` on Windows), `cd folder` (go into a folder, `cd ..` to go up), and `mkdir name` (make a folder). Run your script from the folder it lives in, or give its path.

# When something goes wrong

Every beginner sees errors constantly, and they are not a judgement on you. They are the interpreter telling you what it could not do.

```
  File "about_me.py", line 4
    print("I like tea)
          ^
SyntaxError: unterminated string literal (detected at line 4)
```

Read an error **from the bottom**: the last line names the kind of error and says what happened; the lines above say which file and which line. A **SyntaxError** means the text is not valid Python (a missing quote or bracket, a missing colon), and Python refuses to run any of the file. Other errors appear _while_ the program runs and are covered on later days.

# Habits to start now

- Type the code yourself instead of pasting it. Your fingers learn the shapes.
- Change one thing at a time, run again, and look at what changed.
- Keep each program in its own file with a clear name, in a folder you can find again.
- If you are stuck for 20 minutes, write down what you tried and what you expected, then ask or look it up. Writing it down often shows the answer.
