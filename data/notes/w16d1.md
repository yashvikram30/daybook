# From demo to product

A demo ingests once, trusts everyone, and answers fresh every time. A product must **re-ingest changes**, **enforce who can see what**, **cache**, and **explain what it did** (traces).

# Incremental ingestion

Per source document store `content_hash`. On each run: **unchanged** → skip; **changed** → re-chunk, re-embed, upsert, delete stale chunks; **removed** → delete its chunks. Chunk ids derive from content so reruns are no-ops (idempotent). Bump a **corpus version** whenever anything changes (used for cache keys).

# Tenant isolation

- Store `tenant_id` on **every chunk** (and cache entry, trace, log).
- Enforce the filter **inside the one retrieval function** that every code path must call; make `tenant_id` a **required parameter** (can't call without it), derived from the **authenticated identity**, never from the request body. Optionally **Postgres row-level security** as defense in depth.

```python
def retrieve(tenant_id: str, query: str, k: int = 5) -> list[Chunk]:
    return db.fetch("""SELECT id, text FROM chunks WHERE tenant_id = $1
                       ORDER BY embedding <=> $2 LIMIT $3""", tenant_id, embed(query), k)
```

- **Filtering and ANN:** an HNSW index may scan the nearest candidates _then_ apply the `WHERE`, returning fewer than `k` (or no) rows; pgvector offers **iterative index scans** (`hnsw.iterative_scan`); alternatives: partial indexes, partitioning or a separate index per large tenant.
- **Test it adversarially:** tenant A issues queries that _copy B's text verbatim_, or prompt-inject ("ignore the filter"); assert no B chunk ids ever return. Check the cache, logs and traces for leaks too.
- **Where's the access check?** Server-side, at the single chokepoint, on every request, deny by default. A forgotten check in a new code path is the classic leak, so make it structural (required types, middleware, RLS) and test every endpoint.

# Answer cache

Key = `hash(tenant_id, normalized_question, corpus_version, prompt_version, model)`. When a document changes the corpus version bumps, so old entries become unreachable (coarse but safe); finer-grained: store the **doc ids** each answer used and invalidate those keys. Add a TTL.

**Semantic cache.** An exact-match cache only helps when the same string repeats. A semantic cache embeds each question and, if a past question is within a similarity threshold, returns the stored answer, skipping retrieval and the model. It can cut cost and latency for repeated intents ("how do I reset my password" in a hundred phrasings), but it can be **confidently wrong**: "Can I cancel within 30 days?" vs "…after 30 days?" embed almost identically but have opposite answers; different tenants have different permissions; data goes stale. Use an exact-match cache first; if semantic, set a strict threshold, scope by tenant and corpus version, and expire entries when documents change.

# Tracing

One span per stage: `ask → rewrite → retrieve (vector, bm25) → rerank → generate`, with attributes: tenant (hashed), chunk ids, scores, tokens, cache hit/miss, latency. Tools: Langfuse, OpenTelemetry.

# Incremental ingestion

```python
def ingest(docs):
    seen, changed = set(), False
    for d in docs:
        seen.add(d.id); h = sha256(d.text)
        if store.hash(d.id) == h: continue                       # unchanged
        changed = True
        store.delete_chunks(d.id)
        store.upsert(chunks(d, tenant=d.tenant), doc_hash=h)     # re-embed only here
    for gone in store.doc_ids() - seen:
        store.delete_chunks(gone)
        changed = True
    if changed:
        store.bump_corpus_version()
```

**Test:** run twice → zero writes second time; edit one doc → only its chunks change; delete a doc → its chunks vanish.

# Tenant test

Seed tenants A and B with distinct secret phrases. Query as A with B's exact text and variations; assert returned ids ⊆ A's. Also test the cache: A and B asking the same question must not share entries.

# Cache in the Raft KV

`key = sha256(f"{tenant}|{norm(q)}|{corpus_version}|{prompt_v}")`; `GET` before the pipeline, `PUT` after (use idempotency key). On KV errors: **treat as a miss, don't fail the request**. Spans: `retrieve`, `rerank`, `generate`, `cache.get/put`.

# Shortest paths: counting, negative edges, all pairs

| Algorithm          | Handles                                     | Time           |
| ------------------ | ------------------------------------------- | -------------- |
| Dijkstra           | non-negative weights, single source         | O((V+E) log V) |
| **Bellman-Ford**   | **negative edges**, detects negative cycles | O(V·E)         |
| **Floyd-Warshall** | all pairs, negative edges (no neg. cycles)  | O(V³)          |

**Number of shortest paths:** run Dijkstra; keep `ways[v]`. On a strictly shorter path: `dist[v] = nd; ways[v] = ways[u]`; on an **equal** path: `ways[v] += ways[u]` (mod 1e9+7).

**Bellman-Ford:** relax **all edges V−1 times**; any edge still relaxable in the V-th pass ⇒ a negative cycle reachable from the source.

```python
INF = float("inf")
dist = [INF] * V
dist[src] = 0
for _ in range(V - 1):
    for u, v, w in edges:
        if dist[u] < INF and dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
```

**Floyd-Warshall:** `k` (the allowed intermediate vertices) is the **outer** loop.

```python
for k in range(n):
    for i in range(n):
        for j in range(n):
            if d[i][k] < INF and d[k][j] < INF:
                d[i][j] = min(d[i][j], d[i][k] + d[k][j])
```

**City with the fewest neighbors within a distance threshold:** run Floyd-Warshall, count `d[i][j] <= threshold` per city; pick the minimum (ties → larger index).

# Cache invalidation

"There are only two hard things in computer science: cache invalidation and naming things."

**Key design:** include **every input that changes the answer**: tenant, normalized question, corpus version, prompt version, model. A missing input = wrong answers served as fresh.

| Strategy                | Notes                                                                                   |
| ----------------------- | --------------------------------------------------------------------------------------- |
| **TTL**                 | simple; bounded staleness; tune per data                                                |
| **Invalidate on write** | explicit delete/update when the source changes; easy to miss a path                     |
| **Versioned keys**      | include a version/generation number: new version = old entries unreachable (no deletes) |
| **Dependency tracking** | map doc → cache keys that used it                                                       |

**Pitfalls:** **stampede** (many misses at once hit the backend: use single-flight (one in-flight future per key that every waiter awaits) or locks, and jittered TTLs), **negative caching** of errors, **cold start** overload after a flush, **caches hiding outages and bugs** (backend broken but cache still serving), and unbounded memory. Measure **hit rate** and staleness; make cache failures non-fatal.

1. **Document changed.** Every cached answer that used it is now stale. With the corpus version in the key, all entries from before the change are unreachable (coarse); with dependency tracking only keys tied to that document are invalidated; a TTL bounds the rest.
2. **Access check.** On the server, in the one retrieval function every path calls (plus ideally row-level security), using identity from authentication. A new path that skips it leaks data, so make tenant a required parameter and test every endpoint.
3. **Semantic cache.** Similar embeddings don't mean the same question or permissions: small wording changes can flip the answer, and entries may be stale or cross-tenant, yet the cached answer is returned with full confidence.
