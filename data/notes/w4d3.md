# What an allocator does

Manages a heap: an allocator's `malloc(n)` returns a block of ≥ n bytes aligned (16 B), `free(p)` returns it. Memory comes from the OS in big chunks (`mmap` maps fresh pages; older allocators also move the program break with `sbrk`), and the allocator carves it up.

```
[hdr|payload][hdr|payload (free)][hdr|payload] ...      hdr = {size, free?, next}
 ^p = ptr returned to the caller (hdr sits just before it)
```

- **`free(p)` needs no size** because the header just before `p` records it.
- **Split** a free block if it's much larger than requested. **Coalesce** adjacent free blocks on free.
- Placement: **first-fit** (fast, fragments the front), **best-fit** (tight, slower), next-fit, worst-fit.
- Faster designs: segregated free lists by **size class**, per-thread caches (tcmalloc/jemalloc). CPython's own small-object allocator, `pymalloc`, is a size-class design: requests up to 512 bytes are rounded up to a multiple of 16 and served from fixed-size pools inside large arenas; anything bigger goes to the system allocator.

# Contiguous allocation, segmentation and paging

The simplest scheme gives each process one contiguous block of memory. Choosing the hole is the same problem your allocator solves:

| Placement | Picks                             | Typical result                                      |
| --------- | --------------------------------- | --------------------------------------------------- |
| First fit | the first hole that is big enough | fast; leaves small holes near the start             |
| Best fit  | the smallest hole that fits       | leaves tiny, useless leftovers; needs a full search |
| Worst fit | the largest hole                  | leaves bigger leftovers, but usually performs worst |

With holes of 100, 500, 200, 300 and 600 KB and requests of 212, 417, 112 and 426 KB in order, first fit and worst fit cannot place the 426 KB request, while best fit places all four. No policy is always best.

Contiguous schemes suffer **external fragmentation**; moving blocks together (**compaction**) fixes it at a high price. Two schemes avoid the problem by splitting a process into pieces:

|                        | Segmentation                                                    | Paging                                              |
| ---------------------- | --------------------------------------------------------------- | --------------------------------------------------- |
| Piece                  | variable-sized, matches the program's parts (code, heap, stack) | fixed-sized **pages**, mapped onto equal **frames** |
| Address                | (segment, offset) checked against a limit                       | (page number, offset) translated by a page table    |
| Fragmentation          | external                                                        | internal only, in the last page                     |
| Sharing and protection | natural: share or protect a whole segment                       | per page, through bits in the page-table entry      |

Modern systems use paging, as you saw in week 2, and give each page its own permission bits.

# Fragmentation

|          | Meaning                                               | Example                                       |
| -------- | ----------------------------------------------------- | --------------------------------------------- |
| Internal | wasted space _inside_ an allocated block              | rounding 13 B up to 16 B, headers             |
| External | free memory exists but is split into pieces too small | 3×1 KB free blocks can't serve a 2 KB request |

A header-based first-fit allocator suffers both; size-class allocators trade external for internal.

# Python: reference counting plus a cycle collector

CPython frees an object **the moment its reference count reaches zero**: no pause, and `__del__` or a `with` block runs at a predictable time. Counting alone cannot free objects that refer to each other, so a **generational cycle collector** runs now and then (triggered by allocation counts; `gc.get_threshold()`) and finds unreachable cycles by tracing from the container objects.

| Refcount + cycle GC removes                              | It costs                                                                                                                                                                                                            |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| leaks of unreachable memory, use-after-free, double free | an increment and decrement on nearly every assignment, occasional collector pauses, no compaction (freed memory is reused but often not returned to the OS), cycles that outlive their use until the collector runs |

```python
import gc, sys

class Node: pass
a, b = Node(), Node()
a.other, b.other = b, a          # a cycle
del a, b                          # counts never reach zero
print(gc.collect())               # the collector finds and frees them: number of objects found
sys._debugmallocstats()           # pymalloc arenas, pools and size classes (printed to stderr)
```

Reduce pressure: allocate less, reuse buffers (`bytearray`, `memoryview`), use `__slots__` for many small instances, keep numeric data in `array`/NumPy, and break cycles with `weakref`.

```python
import tracemalloc
tracemalloc.start()
# ... run the code ...
for stat in tracemalloc.take_snapshot().statistics("lineno")[:5]:
    print(stat)                   # the lines that allocated the most memory
```

# Python arena (size classes)

```python
class Arena:
    def __init__(self, size: int) -> None:
        self.buf = bytearray(size)
        self.off = 0
        self.free: dict[int, list[int]] = {}          # size class -> free offsets

    @staticmethod
    def size_class(n: int) -> int:
        return 1 << max(4, (n - 1).bit_length())      # round up to 16, 32, 64, ...

    def alloc(self, n: int) -> int:
        c = self.size_class(n)
        if self.free.get(c):
            return self.free[c].pop()
        if self.off + c > len(self.buf):
            raise MemoryError("arena full")
        off, self.off = self.off, self.off + c        # bump allocate
        return off

    def release(self, off: int, n: int) -> None:
        self.free.setdefault(self.size_class(n), []).append(off)
```

Benchmark it against allocating a fresh `bytearray(n)` each time (`timeit`), and compare an object pool with plain construction in a hot loop. Use `tracemalloc` to count allocations on each side.

# Binary search on the answer

When you're asked for the **minimum X such that a condition holds** (or the maximum of a minimum), and the condition is monotonic in X, binary search X over its range and check feasibility in O(n).

| Problem                                        | Range                     | `feasible(x)`                                             |
| ---------------------------------------------- | ------------------------- | --------------------------------------------------------- |
| Koko eating bananas (min speed k, ≤ h hours)   | `[1, max pile]`           | `Σ ceil(p/k) ≤ h`                                         |
| Min days for m bouquets of k flowers           | `[min bloom, max bloom]`  | count adjacent runs of ≥ k bloomed                        |
| Ship within D days (min capacity)              | `[max weight, Σ weights]` | greedy pack into ≤ D days                                 |
| Painter's / book allocation (minimize the max) | `[max, Σ]`                | greedy: start a new partition when exceeding x; count ≤ K |

```python
def ship_within_days(w: list[int], days: int) -> int:
    lo, hi = max(w), sum(w)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        need, cur = 1, 0
        for v in w:
            if cur + v > mid:
                need += 1
                cur = 0
            cur += v
        if need <= days:
            hi = mid
        else:
            lo = mid + 1
    return lo
```

**Kth missing positive** (sorted array): at index `i`, `a[i] - (i+1)` numbers are missing; binary search the first `i` with missing ≥ k; answer = `k + lo`.

Cost: O(n log(range)).

# Fuzz your allocator

**Property-based testing** generates inputs to find crashes and invariant violations. **Hypothesis** can even generate whole _sequences of operations_, which is exactly what an allocator needs.

```python
from hypothesis import strategies as st
from hypothesis.stateful import RuleBasedStateMachine, invariant, precondition, rule

class ArenaMachine(RuleBasedStateMachine):
    def __init__(self) -> None:
        super().__init__()
        self.arena = Arena(1 << 16)
        self.live: dict[int, int] = {}                 # offset -> requested size

    @rule(n=st.integers(1, 512))
    def alloc(self, n: int) -> None:
        try:
            off = self.arena.alloc(n)
        except MemoryError:
            return
        assert off not in self.live                    # never hand out a live block twice
        self.live[off] = n

    @precondition(lambda self: self.live)
    @rule(data=st.data())
    def release(self, data) -> None:
        off = data.draw(st.sampled_from(sorted(self.live)))
        self.arena.release(off, self.live.pop(off))

    @invariant()
    def no_overlap(self) -> None:
        spans = sorted((o, o + Arena.size_class(n)) for o, n in self.live.items())
        assert all(a[1] <= b[0] for a, b in zip(spans, spans[1:]))

TestArena = ArenaMachine.TestCase
```

Run it with `pytest`. When Hypothesis finds a failure it **shrinks** it to the shortest sequence that still fails, and remembers it in `.hypothesis/` as a regression.

Pick **invariants** to check, not just "doesn't crash".

1. **Fragmentation.** Internal: unused space inside an allocated block (alignment/rounding, headers). External: enough total free space but no contiguous block large enough. A first-fit list allocator suffers external fragmentation mostly (plus header/rounding internal waste); coalescing mitigates it.
2. **No size in `free`.** The allocator stores the block size (and flags) in a header just before the returned pointer, so `free(p)` reads `((hdr*)p - 1)->size`.
3. **Fit policies.** It depends on the trace, which is the point: no policy always wins. **First fit** is fast and tends to leave many small holes near the start of the list. **Best fit** picks the tightest hole, which leaves tiny slivers too small to reuse, and it must search the whole list. **Worst fit** carves up the largest hole, so it often leaves no big block for a later large request (it failed the 426 KB request in the worked example while best fit succeeded). **Next fit** resumes where it left off, spreading allocations across memory and fragmenting the whole heap evenly. Best fit is not always best because the leftover slivers fragment memory and the search is slower, and for other request sequences first fit or even worst fit places everything. Report the numbers from your own trace.
4. **Reference counting and the cycle collector.** They remove leaks of unreachable data, use-after-free and double free (in safe Python code). They cost an increment and decrement on nearly every assignment, occasional collector pauses for cycles, and memory that is reused but often not returned to the OS; and you give up manual control of exactly when memory is released (though refcounting makes that moment predictable).
