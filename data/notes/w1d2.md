# The Hardware Mental Model: Everything is Bits

At the silicon level, a computer knows only two electrical states: voltage on (1) or voltage off (0). A single 0 or 1 is a **bit**.
- **Byte**: Grouping 8 bits together gives a byte (values from 0 to 255 in decimal, or `0x00` to `0xFF` in hexadecimal).
- **Word**: Modern 64-bit CPUs process 64 bits (8 bytes) at a time in a single CPU register.

How does hardware represent complex information using only bits?
1. **Unsigned numbers**: Binary positional notation (`0b1010` = 10).
2. **Negative numbers (Two's Complement)**: An ingenious design where the top bit has negative weight, allowing the CPU to use the exact same addition circuit for both addition and subtraction.
3. **Text**: Characters mapped to byte codes (ASCII and UTF-8).
4. **Decimals (Floats)**: Scientific notation in binary ($(-1)^s \times 1.m \times 2^{e-b}$).

# Integers

- **Two's complement:** an n-bit signed value has weight `-2^(n-1)` on the top bit. `-1` in 8 bits is `1111 1111`. Negate = invert bits + 1.
- Addition hardware is identical for signed and unsigned: same adder, only interpretation differs. That is why two's complement won.
- Range of int8: -128..127 (asymmetric: `-x` overflows for the minimum).
- **Python ints never overflow.** They are arbitrary precision: `2**100` is fine, and `255 + 1` is `256`, not `0`. To see what fixed-width hardware does, mask the result or use `ctypes`. `ctypes.c_int32(2**31).value` shows the wrap-around a 32-bit register would give.

```python
(255 + 1) & 0xFF                      # 0     : what uint8 wraparound gives
((127 + 1 + 128) & 0xFF) - 128        # -128  : what int8 wraparound gives
import ctypes
ctypes.c_uint8(256).value             # 0
ctypes.c_int8(128).value              # -128
```

# Floats (IEEE 754)

`value = (-1)^s × 1.mantissa × 2^(exp-bias)`

| Type    | Sign | Exponent | Mantissa | Precision             |
| ------- | ---- | -------- | -------- | --------------------- |
| float32 | 1    | 8        | 23       | ~7 decimal digits     |
| float64 | 1    | 11       | 52       | ~15-16 decimal digits |

- Python's `float` is always an IEEE 754 double (float64). `float32` appears through `struct` (`"f"`), `ctypes.c_float` or NumPy.
- `0.1` has no finite binary expansion, so `0.1 + 0.2 = 0.30000000000000004`. Never compare floats with `==`; use `math.isclose`.
- 0.5 is `2^-1`, exactly representable. Above `2^53`, float64 cannot represent every integer (spacing > 1), so `float(2**53) + 1 == float(2**53)`.
- Special values: `±inf`, `nan` (`nan != nan`; test with `math.isnan`).

# Endianness

Byte order of a multi-byte value in memory. `0x01020304` on little-endian (x86, arm64 macOS) is bytes `04 03 02 01`. Network protocols use big-endian ("network byte order"). In Python, `sys.byteorder` tells you the machine's order, `int.to_bytes` / `int.from_bytes` take an explicit order, and `struct` uses `<` for little-endian and `>` (or `!`) for big-endian.

# Lists

A `list` is an object holding a pointer to an array of **pointers** to other objects, plus a length and an allocated size. `append` within the allocated size writes the next slot; beyond it, CPython allocates a bigger array (growing by roughly one eighth, plus a little) and copies the pointers.

Assignment never copies. A **slice** of a list _does_ copy (the pointers, not the objects), unlike a slice in some other languages:

```python
a = [1, 2, 3, 4]
b = a[:2]        # new list; no sharing
b.append(99)     # a is still [1, 2, 3, 4]

c = a            # same list, two names
c.append(99)     # a is now [1, 2, 3, 4, 99]
```

To share memory on purpose, use a `memoryview` over a `bytearray`, or a NumPy array slice (a _view_).

# Tuples, dictionaries, sets and strings

| Type    | Mutable | Lookup / `in`       | Use it for                                 |
| ------- | ------- | ------------------- | ------------------------------------------ |
| `list`  | yes     | O(n) scan           | an ordered sequence you change             |
| `tuple` | no      | O(n) scan           | a fixed record; can be a dict key          |
| `dict`  | yes     | O(1) average (hash) | mapping keys to values; keeps insert order |
| `set`   | yes     | O(1) average (hash) | membership tests, removing duplicates      |

- A **dict** is a hash table: the key's `hash()` picks a slot, so keys must be hashable, which in practice means immutable (`str`, `int`, `tuple` of those). Lookups on a missing key raise `KeyError`; use `d.get(k, default)` or `collections.defaultdict`. Since Python 3.7 dicts remember insertion order.
- A **set** is a dict with only keys. `a & b`, `a | b` and `a - b` are intersection, union and difference. `x in some_list` scans the whole list, while `x in some_set` is one hash lookup, which is often the first speed-up to try.
- **Comprehensions** build a collection in one expression: `[x * x for x in nums if x % 2 == 0]`, `{w: len(w) for w in words}`, `{c for c in text}`. A generator expression `(x * x for x in nums)` produces the values one at a time without building a list.
- **Strings** never change in place. Methods return new strings: `split`, `join`, `strip`, `replace`, `startswith`. Build a long string with `"".join(parts)`, not `+=` in a loop, which copies every time. Loop idioms: `for i, x in enumerate(xs)`, `for a, b in zip(xs, ys)`, `for k, v in d.items()`.

```python
counts = {}
for word in text.split():
    counts[word] = counts.get(word, 0) + 1
top = sorted(counts.items(), key=lambda kv: kv[1], reverse=True)[:3]
```

    n = 0
    while x:
        x &= x - 1                     # clears lowest set bit
        n += 1

def is_pow2(x: int) -> bool:

# Quick sort

Pick a pivot, partition so smaller go left and larger go right, recurse on both sides. In-place, not stable.

|                                                                | Time       | Space          |
| -------------------------------------------------------------- | ---------- | -------------- |
| Average / best                                                 | O(n log n) | O(log n) stack |
| Worst (bad pivots, e.g. sorted input with first-element pivot) | O(n²)      | O(n) stack     |

```python
def quick(a: list[int], lo: int, hi: int) -> None:
    if lo >= hi:
        return
    p = a[hi]                       # Lomuto partition, pivot = last
    i = lo
    for j in range(lo, hi):
        if a[j] < p:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    quick(a, lo, i - 1)
    quick(a, i + 1, hi)
```

Python limits recursion depth to about 1000 by default, so a worst-case input on a few thousand items raises `RecursionError`. Picking a random pivot makes that unlikely.

# Recursive versions (pattern)

Turn the outer loop into recursion with a base case.

```python
def bubble(a: list[int], n: int) -> None:   # n = unsorted length
    if n <= 1:
        return
    for j in range(n - 1):
        if a[j] > a[j + 1]:
            a[j], a[j + 1] = a[j + 1], a[j]
    bubble(a, n - 1)                          # largest is now at a[n-1]
```

Insertion: `insertion_rec(a, n)` sorts first `n-1` recursively, then inserts `a[n-1]`.

# How git stores things

Git is a content-addressed object database keyed by SHA hash:

| Object | Holds                               |
| ------ | ----------------------------------- |
| blob   | file contents                       |
| tree   | directory: names → blobs/trees      |
| commit | tree + parent(s) + author + message |
| ref    | name (branch/tag) → commit hash     |

```
HEAD → refs/heads/main → commit C3 → C2 → C1
                          each commit → a tree → blobs
```

Identical content is stored once. Explore: `git cat-file -p HEAD`, `git cat-file -p HEAD^{tree}`. History is immutable; "rewriting" creates new commits.
