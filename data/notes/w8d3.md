# MVCC (multi-version concurrency control)

Never overwrite in place: each write creates a **new version** of the row.

```
key x:  [v1: begin=10, end=20 "a"] [v2: begin=20, end=∞ "b"]
tx with snapshot ts=15 sees "a";  ts=25 sees "b"
visible(version, snap) = begin ≤ snap < end   (and creator committed)
```

- **Readers never block writers, writers never block readers.** Reads come from a consistent snapshot taken at transaction start (or per statement under READ COMMITTED).
- **Write-write conflicts** are detected: **first-committer-wins** (or first-updater-wins): the second writer to the same key aborts/retries.
- **Garbage collection:** old versions are removable once **no active snapshot can see them**: `end_ts <` the oldest active snapshot. Postgres does this with `VACUUM` (tuples carry `xmin`/`xmax`); a long-running transaction pins old versions and causes **bloat**.

# Two-phase locking (2PL)

- **Growing phase:** acquire locks (shared `S` for read, exclusive `X` for write); **shrinking phase:** release. **Strict 2PL** holds all locks until commit/abort (avoids cascading aborts).
- Gives **serializability**, but **readers take shared locks and block/are blocked by writers**, and **deadlocks** are possible (detect with a waits-for graph or timeouts, abort a victim).
- Predicate/gap locks are needed to stop phantoms.

|                   | 2PL                        | MVCC                                      |
| ----------------- | -------------------------- | ----------------------------------------- |
| Reader behavior   | lock, may wait for writers | read snapshot, no waiting                 |
| Writer vs writer  | wait on lock               | conflict detected at write/commit         |
| Cost              | blocking, deadlocks        | storage for versions + GC                 |
| Default isolation | serializable               | snapshot isolation (SSI for serializable) |

Real systems mix both (Postgres: MVCC for reads, row locks for writes).

# The third family: timestamps, and optimism

**Timestamp ordering.** Give every transaction a timestamp at start and make the outcome equal to running them in timestamp order. Each item remembers the largest timestamp that read it (`read_ts`) and wrote it (`write_ts`).

- Transaction `T` **reads** `X`: if `ts(T) < write_ts(X)`, a younger transaction already overwrote it, so `T` aborts and restarts with a new timestamp. Otherwise read, and set `read_ts(X) = max(read_ts(X), ts(T))`.
- Transaction `T` **writes** `X`: if `ts(T) < read_ts(X)` or `ts(T) < write_ts(X)`, abort. Otherwise write and set `write_ts(X) = ts(T)`.

No locks are held, so there are no deadlocks, but conflicts turn into aborts and restarts.

**Optimistic concurrency control (OCC).** Assume conflicts are rare. A transaction has three phases: _read_ (work on private copies), _validate_ (at commit, check that nothing it read was changed by a transaction that committed meanwhile), and _write_ (publish if valid, otherwise abort and retry). It wins when conflicts are rare and loses under contention, when most work is thrown away. The version column used in "compare-and-set" updates is the same idea.

|                     | Pessimistic (locks) | Optimistic (validate) | Timestamps                     |
| ------------------- | ------------------- | --------------------- | ------------------------------ |
| Conflict handled by | waiting             | aborting at commit    | aborting at access             |
| Deadlocks           | possible            | none                  | none                           |
| Best when           | contention is high  | contention is low     | read-heavy, short transactions |

# Versioned store

1. Global monotonically increasing **timestamp** (`itertools.count()` or an int guarded by a lock). `begin()` → `Tx(snap=now)`.
2. Per key: list of versions `Version(val, begin, end)` (or `deleted`). Reads pick the newest version with `begin ≤ snap < end`.
3. `Write` buffers in `tx.writes`. `commit()` under a lock: for each key, if its newest committed version has `begin > tx.snap` → **conflict, abort**; else assign `commitTS`, close old versions' `end = commitTS`, append new ones.
4. **Tests:** snapshot read isolation (a later commit isn't visible); two concurrent writers to one key → exactly one commits; disjoint keys both commit; reads don't block; stress it with many threads and a tiny `sys.setswitchinterval`.
5. (Stretch) GC versions older than the oldest active snapshot.

# Anomaly check

# Monotonic stack: area and span problems

**Trapping rain water** (two pointers, O(1) space): water above `i` = `min(maxLeft, maxRight) − h[i]`.

```python
l, r = 0, len(h) - 1
lm = rm = water = 0
while l < r:
    if h[l] < h[r]:
        lm = max(lm, h[l])
        water += lm - h[l]
        l += 1
    else:
        rm = max(rm, h[r])
        water += rm - h[r]
        r -= 1
```

**Largest rectangle in a histogram:** increasing stack of indices; when a bar is shorter than the top, pop it: its width spans from the new top+1 to the current index − 1.

```python
st: list[int] = []
best = 0
for i in range(len(h) + 1):
    cur = h[i] if i < len(h) else 0                  # sentinel 0 flushes the stack
    while st and h[st[-1]] >= cur:
        top = st.pop()
        left = st[-1] if st else -1
        best = max(best, h[top] * (i - left - 1))
    st.append(i)
```

**Maximal rectangle of 1s:** build a histogram per row (`height[j]++` or reset to 0) and apply the above: O(rows·cols).

**Online stock span:** stack of `(price, span)`; pop while top price ≤ today, accumulate spans; push.

```python
span = 1
while st and st[-1][0] <= p:
    span += st.pop()[1]
st.append((p, span))
```

All O(n).

# Property-based testing

Instead of hand-picked examples, state a **property** that must hold for all inputs, let the library generate hundreds of random cases, and **shrink** a failure to a minimal one.

```python
from hypothesis import given, strategies as st

ops = st.lists(st.one_of(
    st.tuples(st.just("put"), st.text(max_size=3), st.text(max_size=5)),
    st.tuples(st.just("del"), st.text(max_size=3), st.just("")),
))

@given(ops)
def test_matches_model(history):
    store, model = Store(), {}
    for op, k, v in history:                        # random put/delete sequence
        if op == "put":
            store.put(k, v); model[k] = v
        else:
            store.delete(k); model.pop(k, None)
        assert store.snapshot() == model, "diverged"
```

Good properties: **model equivalence** (store vs a trivial map), round trips (`decode(encode(x)) == x`), idempotence, invariants after random histories (including crash/reopen). Hypothesis also has stateful testing (`RuleBasedStateMachine`) for long histories, and it saves failures in `.hypothesis/` so they replay.

1. **MVCC cleanup.** A background process (VACUUM / GC) removes versions no longer visible to any active or future snapshot, i.e. versions whose `end_ts` is older than the oldest running transaction's snapshot. Long transactions delay cleanup.
2. **2PL reader.** It must acquire (and may wait on) a shared lock for every item it reads, and hold it until commit, so it can block on writers and take part in deadlocks. An MVCC reader just reads from its snapshot without locks.
3. **Strict 2PL and cascading aborts.** Under strict 2PL a transaction keeps its **exclusive locks until it commits or aborts**. Nobody else can read or overwrite its uncommitted data in the meantime, so no transaction ever reads a value that might still be rolled back. A **cascading abort** happens when transaction B read A's uncommitted write and A then aborts, forcing B to abort too; since B could not have read it, there is nothing to cascade. (Plain 2PL, which releases locks in the shrinking phase before commit, can cascade.)
4. **Timestamp ordering and a late transaction.** Each item remembers the largest read and write timestamps. If a transaction arrives "too late", for example it wants to read an item already written by a younger transaction, or write an item already read or written by a younger one, then proceeding would contradict the timestamp order, so it is **aborted and restarted with a new, later timestamp**. There are no locks and no deadlocks, only restarts.
