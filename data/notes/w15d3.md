# Grounded answers with citations

Goal: every claim traceable to a retrieved source, and **no answer** when the sources don't contain one.

```
SYSTEM: Answer ONLY from the numbered sources. After each claim cite the source like [2].
        If the sources do not contain the answer, reply exactly: NO_ANSWER.
<sources>
[1] (docs/pg/indexes.html#btree) B-tree indexes ...
[2] ...
</sources>
Question: ...
```

Return `{answer, citations:[chunk_ids]}`. Claude's **citations** feature does this natively: pass documents as `document` blocks with `citations: {"enabled": true}` and the response carries citation objects with the quoted passages.

**Checking that a source supports the claim:** (1) every cited id exists in the **retrieved** set; (2) quoted text appears **verbatim** in the chunk (string match); (3) an **LLM/NLI judge** asks "does this passage support this claim?" on sampled or all answers; (4) human review of a sample. Citations prove _attribution_, not truth.

# Abstention

When retrieval is weak, **refuse instead of guessing**: (a) threshold on the top retrieval/rerank score, (b) instruct the model to say the docs don't answer, (c) optionally check the answer's support. **Who decides the threshold:** the product owner, informed by data: tune on the eval set (answerable vs unanswerable questions) to balance **wrong answers** vs **false refusals**; neither is free.

# Query rewriting

Follow-ups ("what about its pricing?") don't stand alone: rewrite using chat history into a **standalone query** before retrieval. **Risk:** the rewrite can drop constraints, resolve a pronoun wrongly or inject assumptions, changing the question's meaning. Log original + rewritten, retrieve with both if unsure, and test rewrites.

# Contextual retrieval (Anthropic)

Before embedding/indexing, have an LLM write 1-2 sentences situating each chunk in its **whole document** ("This is from the 2023 ACME annual report, section on Q2 revenue…") and **prepend** it to the chunk (for both embeddings and BM25). Anthropic measured large reductions in failed retrievals (≈ 35% embeddings alone, ≈ 49% with BM25, ≈ 67% adding reranking). Prompt caching of the document makes it cheap.

# Other techniques

**HyDE:** embed a _hypothetical answer_ generated by the model and search with it. **Self-RAG:** retrieve only when needed and critique/verify the answer.

# /ask endpoint

```python
def ask(question, history):
    standalone = rewrite(question, history)                       # keep both for logs
    hits = retrieve(standalone, k=5)                              # hybrid + rerank
    if not hits or hits[0].score < THRESHOLD:
        return {"status": "no_answer", "reason": "weak_evidence", "sources": [h.id for h in hits]}
    ctx = "\n".join(f"[{i+1}] ({h.url}) {h.text}" for i, h in enumerate(hits))
    out = llm(SYSTEM, f"<sources>\n{ctx}\n</sources>\nQuestion: {standalone}")
    if out.strip() == "NO_ANSWER": return {"status": "no_answer", "reason": "model_abstained"}
    cited = {int(n) - 1 for n in re.findall(r"\[(\d+)\]", out) if 0 < int(n) <= len(hits)}
    return {"status": "ok", "answer": out, "citations": [hits[i].id for i in sorted(cited)]}
```

- **Unanswerable test:** 10 questions whose answers aren't in the corpus; count how many are refused correctly; vary `THRESHOLD`.
- **Follow-up rewriting:** `("How do I create an index?", "What about on JSON columns?")` should become a standalone question.
- **Contextual chunks (option):** generate the context sentence per chunk, prepend, re-embed; compare retrieval on the same queries.

# Interval DP and word break

**Word break:** `dp[i]` = can `s[:i]` be segmented? `dp[0]=true`; `dp[i] = OR over j<i of dp[j] && s[j:i] ∈ dict`.

```python
words = set(dict_words)
dp = [True] + [False] * len(s)
for i in range(1, len(s) + 1):
    for j in range(i):
        if dp[j] and s[j:i] in words:
            dp[i] = True
            break
```

**Interval DP template:** `dp[i][j]` over the substring/range `i..j`, computed by **increasing length**, trying every split point `k`.

| Problem                                          | Recurrence                                                                                                        |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| **Matrix chain multiplication** (dims `p[0..n]`) | `dp[i][j] = min_k dp[i][k] + dp[k+1][j] + p[i-1]·p[k]·p[j]`                                                       |
| **Burst balloons** (pad `1` at both ends)        | `k` = **last** balloon burst in `(i,j)`: `dp[i][j] = max_k nums[i-1]·nums[k]·nums[j+1] + dp[i][k-1] + dp[k+1][j]` |
| **Count palindromic subsequences**               | `dp[i][j] = dp[i+1][j] + dp[i][j-1] − dp[i+1][j-1]`, plus `dp[i+1][j-1] + 1` if `s[i]==s[j]`                      |

```python
INF = float("inf")
for length in range(2, n + 1):
    for i in range(1, n - length + 2):
        j = i + length - 1
        dp[i][j] = INF
        for k in range(i, j):
            dp[i][j] = min(dp[i][j], dp[i][k] + dp[k + 1][j] + p[i - 1] * p[k] * p[j])
```

Think "**last** action" (last balloon, last multiplication) so the two sides are independent. Time O(n³).

# Errors and abstention as first-class results

"I don't know" is a **normal outcome** of a RAG system, not an exception. If you hide it (a fake answer, a bare `500`), users and monitoring can't tell it from success.

- Model it in the **type**: `Answer | NoAnswer(reason)` where reasons are enumerated (`no_evidence`, `model_abstained`, `retrieval_empty`, `policy_blocked`).
- API: return `200` with `{"status":"no_answer","reason":...}` for domain outcomes; reserve `4xx/5xx` + **RFC 9457 problem details** for real errors (bad input, upstream outage, timeout).
- The **UI** shows a helpful message and next steps (rephrase, browse sources).
- **Measure** it: abstention rate, correct vs false refusals; alert on sudden shifts (a broken index looks like "everyone gets no answer").
- Log the retrieved ids and scores for each abstention so you can inspect them.

```json
{ "status": "no_answer", "reason": "weak_evidence", "top_score": 0.31, "sources": ["c91f", "a02b"] }
```

1. **Does the source support the claim?** Check the cited id was actually retrieved, that quoted spans appear verbatim in the chunk, and use an NLI/LLM judge (with a rubric) on the claim + passage; spot-check by hand. A citation shows attribution, not necessarily correctness.
2. **No relevant retrieval.** Abstain with a structured "no answer" result (not a guess). The threshold is a product decision made from data: tune on answerable/unanswerable eval questions, weighing wrong answers against false refusals.
3. **Rewrite risk.** A rewrite makes the query standalone (resolving "it", "that"), which helps retrieval, but it can also drop constraints or add assumptions, silently changing the question. Keep and test the original and rewritten forms.
