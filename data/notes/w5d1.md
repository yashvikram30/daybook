# The layers (TCP/IP model)

| Layer              | Job                                   | Examples                               | Identifier        |
| ------------------ | ------------------------------------- | -------------------------------------- | ----------------- |
| Application        | what the programs say                 | HTTP, DNS, TLS, SSH                    | headers, URLs     |
| Transport          | process-to-process delivery           | TCP (reliable stream), UDP (datagrams) | **port** (16-bit) |
| Network / Internet | host-to-host across networks, routing | IP (v4/v6), ICMP                       | **IP address**    |
| Link               | one hop on one network                | Ethernet, Wi-Fi                        | **MAC address**   |

**Encapsulation:** each layer wraps the one above with its own header.

```
[Ethernet hdr][IP hdr][TCP hdr][HTTP: GET / ...][Eth trailer]
```

Answer to "which layer?": MAC → link; IP address → network; port → transport; HTTP header → application.

# OSI versus TCP/IP

The OSI model has seven layers; the TCP/IP model that the internet uses folds them into four.

| OSI                                      | TCP/IP      | What it does                               |
| ---------------------------------------- | ----------- | ------------------------------------------ |
| 7 Application, 6 Presentation, 5 Session | Application | the program's own protocol and data format |
| 4 Transport                              | Transport   | process to process: ports, reliability     |
| 3 Network                                | Internet    | host to host across networks: IP, routing  |
| 2 Data link, 1 Physical                  | Link        | one hop: frames, MAC addresses, signals    |

OSI is the vocabulary for exam questions ("a layer-2 switch", "a layer-7 load balancer"); TCP/IP is what you actually run. **Encapsulation** wraps each layer's data in that layer's header on the way down and unwraps it on the way up.

# Switching and delay

- **Circuit switching** reserves a path for the whole conversation (the old telephone network). Delay is steady and there is no loss, but there is a setup step and the reserved capacity is wasted whenever nobody is talking.
- **Packet switching** cuts data into packets that share links. Each router _stores and forwards_ a whole packet, so capacity is used by whoever has data (statistical multiplexing), at the price of queues and loss. In a **datagram** network every packet carries the destination and is routed on its own (IP). In a **virtual-circuit** network a path is set up first and packets carry a short circuit ID (ATM, MPLS).
- A packet's delay at each hop is **processing** (read the header) + **queuing** (wait for the link) + **transmission** (`packet size / link rate`) + **propagation** (`distance / signal speed`). A 1500-byte packet on a 100 Mb/s link takes 0.12 ms to transmit, while a trip across a continent costs about 20 ms of propagation however fast the link is.

# The link layer: Ethernet, switches and ARP

An Ethernet **frame** is: destination MAC (6 bytes), source MAC (6), type (2), payload (46 to 1500), and a CRC-32 (4). A **MAC address** names a network card and is used only within one local network.

- **CSMA/CD** (the original shared-cable Ethernet): _listen_ before sending; if the line is quiet, send; if you detect a collision while sending, stop, send a jam signal, and wait a random time. After the _n_-th collision of the same frame, pick a random wait of 0 to 2ⁿ − 1 slot times (**binary exponential backoff**), which spreads out the retries. The 64-byte minimum frame exists so a sender is still transmitting when news of a collision comes back. Wi-Fi uses CSMA/**CA** instead (avoid, because it cannot hear while it transmits).
- A **hub** repeats every bit to all ports, so all its ports form one **collision domain**. A **switch** reads the frame, **learns** which port each source MAC is on, and forwards by destination MAC (flooding when the destination is unknown), so each port is its own collision domain. A **router** forwards by IP address and separates **broadcast domains**.
- **ARP** finds the MAC for an IP address on the same network: broadcast "who has 192.168.1.7?", and the owner replies directly. Hosts cache the answer. To reach an address outside the subnet, a host ARPs for its **default gateway's** MAC and sends the frame there.

# Sockets API

`socket → bind → listen → accept` (server), `socket → connect` (client), then `recv/send`, `close`. Python's `socket` module is a thin wrapper over the operating system's socket calls:

```python
import socket, threading

def handle(conn: socket.socket, addr) -> None:
    with conn:                                   # closes on exit
        while data := conn.recv(4096):           # b"" means the peer closed
            conn.sendall(data)                   # echo; sendall loops until everything is sent

srv = socket.create_server(("", 9000))           # socket + bind + listen
while True:
    conn, addr = srv.accept()                    # blocks for a client
    threading.Thread(target=handle, args=(conn, addr), daemon=True).start()   # one thread per connection
```

The same server on one thread with `asyncio`:

```python
import asyncio

async def handle(reader: asyncio.StreamReader, writer: asyncio.StreamWriter) -> None:
    while data := await reader.read(4096):
        writer.write(data)
        await writer.drain()                     # wait if the peer is slow to read
    writer.close()
    await writer.wait_closed()

async def main() -> None:
    server = await asyncio.start_server(handle, "", 9000)
    async with server:
        await server.serve_forever()

asyncio.run(main())
```

Client: `conn = socket.create_connection(("localhost", 9000))`. `conn.settimeout(5)` bounds reads/writes (they raise `TimeoutError`). TCP is a **byte stream**: message boundaries are not preserved, one `recv` may return part of a message or two. `send` can also send only part of the data; `sendall` handles that.

A thread per connection is simple but each thread reserves a stack of megabytes of address space and is scheduled by the kernel; an asyncio task is a small object, and the event loop multiplexes waiting through epoll/kqueue, so tens of thousands of idle connections are cheap.

# Steps

1. Echo server as above (threaded first, then the asyncio version); log `addr`; handle errors on `accept`.
2. Client: connect, send a line, read the reply (use `conn.makefile().readline()`, or loop on `recv` until you have a newline). Test with `nc` and your own.
3. Capture with `sudo tcpdump -i lo0 -n -X port 9000` while connecting and sending. Annotate by layer: the **loopback/link** header, **IP** (127.0.0.1 → 127.0.0.1, protocol 6), **TCP** (ports, flags `S`, `S.`, `.`, `P.`, `F.`, seq/ack numbers), then your payload.
4. Run two clients at once to confirm concurrency works.

# Gotchas

- The `accept` loop must not exit on a single error from one client (catch `OSError` around the per-connection work, not the loop).
- Always close the connection: use `with conn:`.

# Binary search on partitions / answers

**k-th element of two sorted arrays:** like the median problem. Binary search how many elements `i` to take from the smaller array `a` (and `k-i` from `b`), with `i ∈ [max(0,k-n), min(k,m)]`, until `aL ≤ bR` and `bL ≤ aR`. Answer `max(aL, bL)`. O(log(min(m,k))).

**Minimize the maximum distance to gas stations** (add K stations): binary search a **real** answer `d`; `feasible(d)` = `Σ ceil(gap/d) - 1 ≤ K`. Loop until `hi - lo < 1e-6`.

**Split array largest sum:** same as painter's partition: search `[max, Σ]`, greedy count of parts.

**Row with most 1s** (rows sorted): per row `n - lower_bound(row, 1)`, O(m log n). Or staircase from the top-right: if `1`, move left, else down: O(m+n).

```python
# staircase on a sorted-per-row 0/1 matrix
r, c, best = 0, n - 1, -1
while r < m and c >= 0:
    if mat[r][c] == 1:
        best = r
        c -= 1
    else:
        r += 1
```

Binary search over **real numbers** uses an epsilon/iteration count instead of `lo < hi`.

# Test the network without a network

Tests that need real sockets are slow and flaky. Instead:

- **`socket.socketpair()`**: two connected sockets in one process, for testing protocol code without a listening port.
- **A server fixture on port 0**: binding to port `0` asks the OS for a free port, so tests never collide; read it back with `getsockname()`.
- **Fake the other end**: depend on file-like objects or a small interface, not on a concrete socket, so a test can pass `io.BytesIO` or a stub.
- **`http.server` and `unittest.mock`** for quick fakes; the `pytest-asyncio` plugin for `async def` tests.

```python
import socket, threading
import pytest

@pytest.fixture
def echo_port():
    srv = socket.create_server(("127.0.0.1", 0))     # port 0: any free port
    port = srv.getsockname()[1]
    def serve():
        conn, _ = srv.accept()
        with conn:
            conn.sendall(conn.recv(1024))
    threading.Thread(target=serve, daemon=True).start()
    yield port
    srv.close()

def test_echo(echo_port):
    with socket.create_connection(("127.0.0.1", echo_port), timeout=2) as c:
        c.sendall(b"hi")
        assert c.recv(1024) == b"hi"
```

1. **Layers.** MAC → link; IP address → network; port → transport; HTTP header → application.
2. **Switch versus hub, and backoff.** A hub repeats every bit to all ports and knows nothing. A **switch** reads each frame, **learns** which port each source MAC address is on, and forwards by destination MAC to that port only (flooding only when the destination is unknown), so each port is a separate collision domain. After a collision in CSMA/CD, stations back off for a **random** time because identical waits would make them collide again; the range doubles with each successive collision (binary exponential backoff), which spreads retries out when many stations are contending.
3. **Thread vs task.** A thread has a large stack reserved by the OS (megabytes of address space) and is scheduled by the kernel, so thousands are costly. An asyncio task is a small Python object whose coroutine is resumed by the event loop in user space at each `await`, so tens of thousands are practical, provided no task blocks the loop. For 10,000 mostly idle connections choose asyncio tasks.
