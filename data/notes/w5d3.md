# HTTP/1.1 is text over TCP

```
GET /hello?name=ada HTTP/1.1\r\n          request line: method, target, version
Host: example.com\r\n                    headers (Host is required in 1.1)
Accept: */*\r\n
\r\n                                     blank line ends the headers
(optional body)

HTTP/1.1 200 OK\r\n                      status line
Content-Type: text/plain\r\n
Content-Length: 5\r\n
\r\n
hello
```

Lines end in **CRLF**. Header names are case-insensitive.

# Where does the body end?

1. `Content-Length: N` → read exactly N bytes.
2. `Transfer-Encoding: chunked` → repeated `size-in-hex CRLF data CRLF`, ended by a `0` chunk.
3. (Responses only) none of those → until the server closes the connection.

Get it wrong and you hang waiting, truncate the body, or read the next request as body. Disagreement between a proxy and a server about length is **request smuggling**.

# Persistent connections (keep-alive)

HTTP/1.1 keeps the TCP connection open by default (`Connection: close` opts out). Saves a TCP (and TLS) handshake and slow-start per request. New problems: servers must manage idle connections (idle timeouts, resource limits), and requests on one connection are answered **in order**, so a slow response blocks later ones (head-of-line blocking; browsers open ~6 connections per host).

# Looking at HTTP with curl

`curl -v http://localhost:8080/hello` prints the request line and headers it sends (lines starting `>`) and the response headers (lines starting `<`), so you can check your server byte for byte. Useful flags: `-i` (include response headers), `-X POST -d 'a=1'` (method and body), `-H 'Header: value'`, `--http1.1`, `--data-binary @file`, and `--next` to send two requests on one connection and watch keep-alive.

# Methods

| Method             | Safe (no side effects) | Idempotent (repeat = same effect) |
| ------------------ | ---------------------- | --------------------------------- |
| GET, HEAD, OPTIONS | yes                    | yes                               |
| PUT, DELETE        | no                     | yes                               |
| POST               | no                     | **no**                            |
| PATCH              | no                     | not guaranteed                    |

Idempotent methods may be retried automatically; POST needs an idempotency key.

# Status classes

`1xx` info · `2xx` success (200, 201, 204) · `3xx` redirect (301, 302, 304) · `4xx` client error (400, 401, 403, 404, 409, 429) · `5xx` server error (500, 502, 503, 504).

# Parsing

```python
r = conn.makefile("rb")                               # a buffered reader over the socket
line = r.readline().decode("latin-1")                 # "GET /x HTTP/1.1\r\n"
method, target, version = line.split()
hdr: dict[str, str] = {}
while True:
    l = r.readline().decode("latin-1").rstrip("\r\n")
    if l == "":
        break                                         # blank line: headers done (also stop on EOF)
    k, _, v = l.partition(":")
    hdr[k.lower()] = v.strip()
n = int(hdr.get("content-length", 0))
body = r.read(n) if n > 0 else b""                    # read(n) on a buffered reader blocks until n bytes or EOF
```

Response: `conn.sendall(f"HTTP/1.1 200 OK\r\nContent-Length: {len(b)}\r\nContent-Type: text/plain\r\n\r\n".encode() + b)` where `b` is the body as bytes. Note that `Content-Length` counts **bytes**, so measure the encoded body, not the `str`.

# Keep-alive

Loop reading requests on the same buffered reader until EOF/`Connection: close`; set a socket timeout per request. Verify: `curl -v http://localhost:8080/a http://localhost:8080/b` should say "Re-using existing connection".

# Tests

Connect with a raw `socket.create_connection`, write the bytes by hand (including malformed requests, a body shorter than `Content-Length`), assert the response bytes. Limit header size and body size.

# Strings in Python

A `str` is an **immutable sequence of Unicode code points**. `s[i]` is a one-character `str`, `len(s)` counts code points, and `for c in s` yields them. Convert with `list(s)` to modify, `s.encode()` to get UTF-8 `bytes`, and `"".join(parts)` (not `+=` in a loop) to build. `ord(c)` and `chr(n)` convert between characters and code points.

```python
for c in s:                       # characters (code points)
    ...
for i in range(len(s)):           # by index
    c = s[i]
b = s.encode()                    # bytes: len(b) can be larger than len(s) for non-ASCII
```

# Patterns

**Parentheses depth counter** (no stack needed for one bracket type):

```python
# remove outermost parentheses: skip the paren that opens at depth 0 / closes back to 0
depth, out = 0, []
for c in s:
    if c == "(":
        if depth > 0:
            out.append(c)
        depth += 1
    else:
        depth -= 1
        if depth > 0:
            out.append(c)
result = "".join(out)
```

Max nesting depth = max `depth`. Valid parentheses with several types → **stack** (a Python `list` with `append`/`pop`).

**Roman to integer:** if a symbol is smaller than the next, subtract it, else add.

**atoi:** skip leading spaces, optional sign, read digits, **clamp to int32** while accumulating (Python ints do not overflow, so clamp explicitly to `[-2**31, 2**31 - 1]`).

**Longest palindromic substring:** expand around each centre (odd and even), O(n²) time, O(1) space.

```python
def expand(l: int, r: int) -> int:
    while l >= 0 and r < len(s) and s[l] == s[r]:
        l -= 1
        r += 1
    return r - l - 1
```

**Sum of beauty of all substrings** (beauty = max freq − min freq): for each start `i`, extend `j`, maintain `[0] * 26`, compute max/min over non-zero: O(26·n²).

# Design HTTP APIs deliberately

- **Resources as nouns**, methods as verbs: `GET /users/42`, `POST /users`, `DELETE /users/42`.
- Use the **right status codes** (201 + `Location` on create, 204 no body, 400 bad input, 404 missing, 409 conflict, 429 rate limit).
- Respect **safe/idempotent** semantics; make `PUT`/`DELETE` idempotent; accept an **`Idempotency-Key`** on POSTs that must not double-apply.
- Consistent **error shape** (`{"error": {"code": "...", "message": "..."}}`), consistent naming, pagination, versioning (`/v1`).
- Validate input and limit sizes; set `Content-Type`.

1. **Body end.** `Content-Length` (exact byte count), or `Transfer-Encoding: chunked` (terminated by a zero-size chunk), or (for responses) connection close. If wrong the reader hangs, truncates, or interprets leftover bytes as the next request, which is the basis of request-smuggling attacks.
2. **Keep-alive.** Saves repeated TCP/TLS handshakes and slow-start. Costs: the server must hold idle connections (needs idle timeouts and limits), and in-order responses create head-of-line blocking on one connection.
