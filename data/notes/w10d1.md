# Replicated log

Goal: every node's state machine applies the **same commands in the same order**. The leader appends client commands to its log and replicates them; once **committed** (stored on a majority) they are applied.

```
index:   1    2    3    4    5
term:    1    1    1    2    2
cmd:    x=1  y=2  x=3  y=9  z=4        entry = (term, command)
```

# AppendEntries

`AppendEntries(term, leaderId, prevLogIndex, prevLogTerm, entries[], leaderCommit)`; also the heartbeat when `entries` is empty.

Follower:

1. `term < currentTerm` → reject.
2. **Consistency check:** if its log has no entry at `prevLogIndex` with term `prevLogTerm` → reject.
3. If an existing entry **conflicts** with a new one (same index, different term) → delete it and everything after; append new entries not already present.
4. `commitIndex = min(leaderCommit, index of last new entry)`.

Leader keeps `nextIndex[f]` and `matchIndex[f]`; on rejection it **decrements `nextIndex[f]` and retries** (log repair) until the logs match, then overwrites the follower's tail.

# Safety properties

- **Log matching:** if two logs share an entry with the same index and term, the logs are identical up to there (enforced by the prev check).
- **Election restriction:** a candidate wins only if its log is **at least as up-to-date** as a majority's, so the leader always has every committed entry.
- **Leader completeness / state-machine safety:** committed entries are never lost or reordered.

# Commit rule

Leader advances `commitIndex` to `N` when a **majority** have `matchIndex ≥ N` **and `log[N].term == currentTerm`**. A leader never commits **older-term entries by counting replicas**; they become committed indirectly once a current-term entry after them commits. Reason: an old-term entry on a majority can still be overwritten by a later leader that didn't have it (Raft paper Figure 8).

# Uncommitted entries on a deposed leader

It steps down on seeing a higher term; its unreplicated/uncommitted entries are **overwritten** by the new leader's log through log repair (clients of those writes got no success reply, so they must retry).

```python
for N in range(len(log) - 1, commit_index, -1):
    if log[N].term == current_term and count_match(N) > n // 2:
        commit_index = N
        break
```

# Steps

1. **AppendEntries handler** exactly per rules 1-4 above. Return `(term, success, conflict_index, conflict_term)` so the leader can back up faster than one step at a time.
2. **Leader replication:** after a client command, append locally, then per follower send entries from `nextIndex[f]`; on success `matchIndex[f] = prev + len(entries)`, `nextIndex[f] = matchIndex[f] + 1`; on failure decrement/jump back.
3. **Commit:** the loop above, then wake an **applier task** that feeds `log[last_applied+1 .. commit_index]` into the KV state machine through an `asyncio.Queue`, in order.
4. **Persist** `currentTerm`, `votedFor`, `log` before replying to any RPC (write + fsync).
5. **Tests on faultnet:** one command replicates to all; leader crash → new leader keeps committed entries; random partitions + message loss while clients write, then check that all nodes' applied sequences are **identical prefixes**; repeat it over 100 seeds.

# Common bugs

Holding a lock (or assuming nothing changed) across an RPC; using stale `currentTerm` after an RPC returns; forgetting to truncate conflicting entries _only on real conflict_ (don't truncate on a duplicate/older RPC); committing old-term entries by counting.

# Lowest common ancestor and tree distance

**LCA (binary tree):** if the node is `p` or `q` (or `None`) return it; recurse both sides; if both sides return non-None, this node is the LCA.

```python
def lca(n: TreeNode | None, p: TreeNode, q: TreeNode) -> TreeNode | None:
    if n is None or n is p or n is q:
        return n
    l, r = lca(n.left, p, q), lca(n.right, p, q)
    if l and r:
        return n
    return l or r
```

**Maximum width:** BFS carrying each node's **index** (`2i`, `2i+1`); width of a level = `last − first + 1`. Normalize indices by subtracting the level's first index (Python ints cannot overflow, but in C or Java the raw indices would).

**Nodes at distance K / burn a tree from a node:** build a **parent map** (so the tree becomes an undirected graph), then BFS from the target for K levels (or until all nodes are reached: number of levels = burn time).

```python
from collections import deque

parent: dict[TreeNode, TreeNode] = {}                # fill by DFS (TreeNode must be hashable: use @dataclass(eq=False))
q, seen = deque([target]), {target}
for _ in range(k):
    if not q:
        break
    for _ in range(len(q)):
        n = q.popleft()
        for nb in (n.left, n.right, parent.get(n)):
            if nb and nb not in seen:
                seen.add(nb)
                q.append(nb)
# answer: nodes remaining in q
```

Complexity: O(n).

# Deterministic tests

Flaky tests teach people to ignore failures. Make failures **reproducible**:

- **Seed all randomness** and print the seed; replay with the same seed (`SEED=123 pytest`).
- Inject a **fake clock** and fake network; advance time explicitly instead of `sleep`.
- Control scheduling: run a **single-threaded event loop** that processes messages in a seeded order (deterministic simulation testing: FoundationDB, TigerBeetle).
- No real network, disk or time inside the logic under test.
- When a randomized test fails, **save the seed + minimized schedule** as a regression test.

```python
import os, random, time

seed = int(os.environ.get("SEED") or time.time_ns())
print(f"seed={seed}")                    # pytest shows it when the test fails
rng = random.Random(seed)
```
