# Why classes

So far data and the code that uses it are separate: a dictionary here, functions there. A **class** bundles them. It is a blueprint; an **object** (instance) is one thing built from it. A `BankAccount` class describes what every account has (an owner, a balance) and can do (deposit, withdraw); each account you create is an object with its own balance.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("not enough money")
        self.balance -= amount

    def __str__(self):
        return f"{self.owner}: {self.balance}"

acct = BankAccount("Ada", 100)
acct.deposit(50)
print(acct)               # Ada: 150
```

# The pieces

- `class Name:` defines it (use `CapitalizedWords`).
- `__init__` is the **constructor**, called when you write `BankAccount("Ada", 100)`. It sets up the object's starting state.
- **`self`** is the object the method was called on. Python passes it automatically as the first argument: `acct.deposit(50)` runs `BankAccount.deposit(acct, 50)`. That is why `self.balance` in a method means _this_ account's balance.
- Variables on `self` are **attributes** (the data); functions defined in the class are **methods** (the behaviour).
- Special "dunder" methods hook into the language: `__str__` is what `print` shows, `__repr__` is the developer view, `__eq__` defines `==`, `__len__` defines `len(x)`.

# Things to get right

- Each object has its own attributes: two accounts do not share a balance. A variable defined in the class body but outside any method is shared by all objects (a **class attribute**), which is occasionally useful, and a source of surprise with lists.
- Objects are passed by reference: `b = acct` gives two names for one account. Make a separate one with a new call to the class.
- Put checks in the methods (`withdraw` refuses overdrafts) so the object can never be left in an invalid state. That is the real reason to use a class: it protects its own rules.
- Keep classes small and named after one thing. If you cannot say in a sentence what a class is, split it.

For plain records with little behaviour, `from dataclasses import dataclass` writes `__init__`, `__repr__` and `__eq__` for you from just the field list.
