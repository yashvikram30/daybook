# Passwords

Never store plaintext or fast hashes (MD5/SHA-256 alone). Use a **slow, salted, memory-hard** hash: **argon2id** (OWASP baseline ≥ 19 MiB memory, 2 iterations, 1 lane), or scrypt/bcrypt. Salt is unique per user and stored with the hash; compare in constant time (`hmac.compare_digest`). In Python use the `argon2-cffi` package (`PasswordHasher().hash(pw)` and `.verify(hash, pw)`), or the standard library's `hashlib.scrypt`.

# Firewalls

A **firewall** allows or blocks traffic by rule. A **packet filter** looks at each packet's header only (source and destination IP, protocol, ports, TCP flags) and applies the first matching rule, ending in a default of _deny_. It is fast but has no memory. A **stateful** firewall also tracks connections, so it allows a reply to a connection that started inside and drops unsolicited inbound packets. An **application** (proxy) firewall understands the protocol, for example HTTP, and can inspect the content. Layers stack: a filter at the network edge, then per-service rules, then authentication in the application. Treat the firewall as one control, not the whole defence.

# HTTP/2 (and 3)

HTTP/2: **binary framing**, many **multiplexed streams** on one connection (no HTTP-level head-of-line blocking), **HPACK** header compression. TCP-level HOL blocking remains. **HTTP/3** runs over **QUIC (UDP)**: independent streams, built-in TLS 1.3, faster setup.

# Load balancing

- **L4** balances TCP connections; **L7** understands HTTP (routing by path/header, TLS termination).
- Algorithms: round robin, weighted, **least connections**, IP/consistent hash (stickiness).
- **Health checks:** _active_ (probe `/healthz` every few seconds; mark down after N consecutive failures/timeouts, up after M successes) and _passive_ (watch real traffic errors). A **slow** backend is the hard case: treat latency above a threshold as a failure, use timeouts, retries on _idempotent_ requests, circuit breakers, latency-aware balancing.

```python
# the core of a reverse proxy: copy bytes both ways between the client and a chosen backend
async def pipe(r: asyncio.StreamReader, w: asyncio.StreamWriter) -> None:
    while chunk := await r.read(65536):
        w.write(chunk)
        await w.drain()
    w.close()
```

Write that for TCP first (an L4 proxy), then parse the request line and headers to make it an L7 proxy that can route, add `X-Forwarded-For` and retry.

# Round-robin proxy with health checks

```python
import asyncio, itertools
from dataclasses import dataclass

@dataclass
class Backend:
    host: str
    port: int
    alive: bool = True
    fails: int = 0
    oks: int = 0

class Pool:
    def __init__(self, backends: list[Backend]) -> None:
        self.backends = backends
        self._rr = itertools.count()

    def pick(self) -> Backend | None:                # skip dead backends, at most len tries
        for _ in range(len(self.backends)):
            b = self.backends[next(self._rr) % len(self.backends)]
            if b.alive:
                return b
        return None                                   # -> 503
```

Health loop (an asyncio task): every 2 s `GET /healthz` with a 500 ms `asyncio.timeout`; flip `alive` after 2 consecutive failures/successes. All of this runs on one thread, so the pool needs no lock.

# Rate limiting per IP

Token bucket: a dict `ip → bucket`, where a bucket stores `tokens` and `last` (a `time.monotonic()` value). On each request add `(now - last) * rate` tokens up to the burst size, then take one if available. Evict idle entries (or use a TTL cache). On limit exceeded return `429` with `Retry-After`. Take the IP from the connection's peer address (trust `X-Forwarded-For` only from your own proxy).

```python
def allow(b: Bucket, now: float, rate: float = 5, burst: int = 10) -> bool:
    b.tokens = min(burst, b.tokens + (now - b.last) * rate)
    b.last = now
    if b.tokens >= 1:
        b.tokens -= 1
        return True
    return False
```

Threads would need a lock around this read-modify-write; in a single asyncio loop it is safe because nothing awaits in between.

# Sliding window with counts

**At most K distinct characters (longest):** map of counts; shrink while `len(map) > k`.

```python
from collections import Counter

cnt: Counter[str] = Counter()
l = best = 0
for r, ch in enumerate(s):
    cnt[ch] += 1
    while len(cnt) > k:
        cnt[s[l]] -= 1
        if cnt[s[l]] == 0:
            del cnt[s[l]]
        l += 1
    best = max(best, r - l + 1)
```

**Longest repeating character replacement:** window valid if `size − maxFreq ≤ k`. (`maxFreq` never needs to decrease: it only matters when it grows.)

**Minimum window substring:** `need` counts from `t`; `missing = len(t)`; expand `r` (decrement `missing` when a needed char is covered), then shrink `l` while `missing == 0`, recording the smallest window.

```python
from collections import Counter

need = Counter(t)
missing = len(t)
l, best_len, best_l = 0, float("inf"), 0
for r, ch in enumerate(s):
    if need[ch] > 0:
        missing -= 1
    need[ch] -= 1
    while missing == 0:
        if r - l + 1 < best_len:
            best_len, best_l = r - l + 1, l
        need[s[l]] += 1
        if need[s[l]] > 0:
            missing += 1
        l += 1
```

**Minimum window subsequence:** characters must appear **in order**; scan forward to match all of `t`, then backward from the end to find the tightest start; continue from there (O(n·m)), or DP.

Exactly-K counting trick (next day): `atMost(k) − atMost(k−1)`.

# Threat modelling

Ask four questions (OWASP / Shostack):

1. **What are we building?** Draw a data-flow diagram: actors, processes, data stores, **trust boundaries** (where data crosses from untrusted to trusted).
2. **What can go wrong?** Walk each element with **STRIDE**.
3. **What are we going to do about it?** Mitigate, accept, transfer or avoid; rank by likelihood × impact.
4. **Did we do a good job?** Review, test the mitigations, revisit when the design changes.

Output: a one-page table of threat → mitigation → owner. Do it at **design time**, when changes are cheap.
