# Building a CPU: The Core Architecture

Every CPU, from the 1970s microprocessors to modern smartphone chips, is built on four core components:

1. **Memory (RAM)**: An array of bytes holding both program instructions and data.
2. **Registers**: A handful of named memory slots inside the CPU (`R0`..`R3` or `V0`..`VF`) that hold numbers currently being worked on.
3. **Program Counter (PC)**: An integer register holding the memory address of the next instruction to execute.
4. **Instruction Decoder**: Logic that reads an instruction, identifies the **Opcode** (what operation to do, like ADD or JUMP), and reads the operands (which registers or addresses to use).

# Fetch-decode-execute

```
loop:  opcode = mem[pc]<<8 | mem[pc+1]   // fetch (CHIP-8 opcodes are 2 bytes)
       pc += 2
       switch opcode & 0xF000 { ... }     // decode by nibbles
       // execute: change registers/memory/display
```

# CHIP-8 machine

| Part        | Spec                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| Memory      | 4096 bytes; programs load at `0x200`; font sprites conventionally at `0x050` |
| Registers   | `V0`-`VF` (8-bit); **`VF` is the flag** (carry/collision)                    |
| `I`         | 16-bit index register (address)                                              |
| `PC`, stack | program counter; call stack (16 entries is typical)                          |
| Timers      | delay and sound, decrement at **60 Hz**                                      |
| Display     | 64×32 monochrome; sprites are XORed                                          |
| Input       | 16-key hex keypad                                                            |

Core opcodes (`X`, `Y` = register, `N`/`NN`/`NNN` = immediates):

| Opcode                         | Effect                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------- |
| `00E0`                         | clear screen                                                                 |
| `00EE` / `2NNN`                | return / call subroutine                                                     |
| `1NNN`                         | jump to NNN                                                                  |
| `3XNN`, `4XNN`, `5XY0`, `9XY0` | skip next instruction if Vx==NN / !=NN / ==Vy / !=Vy                         |
| `6XNN`, `7XNN`                 | Vx = NN; Vx += NN (no carry flag)                                            |
| `8XY_`                         | arithmetic/logic Vx op Vy (`4` add with carry in VF, `5`/`7` subtract)       |
| `ANNN`                         | I = NNN                                                                      |
| `DXYN`                         | draw N-byte sprite from `mem[I]` at (Vx, Vy); VF = 1 if any pixel turned off |

# Python design

```python
from dataclasses import dataclass, field

@dataclass
class CPU:
    mem: bytearray = field(default_factory=lambda: bytearray(4096))
    v: list[int] = field(default_factory=lambda: [0] * 16)
    i: int = 0
    pc: int = 0x200
    stack: list[int] = field(default_factory=list)
    delay: int = 0
    sound: int = 0
    display: list[list[bool]] = field(default_factory=lambda: [[False] * 64 for _ in range(32)])

    def step(self) -> None:
        op = self.mem[self.pc] << 8 | self.mem[self.pc + 1]
        self.pc += 2
        self.exec(op)
```

Separate the **CPU** (state + `step`) from the **machine** (display, keyboard, timers, ROM loading) so the core is testable without I/O. Python integers do not wrap, so every 8-bit result needs an explicit `& 0xFF` and every 16-bit one `& 0xFFFF`.

# Order of work

1. Class + `load_rom(data: bytes)` copying into `mem[0x200:0x200 + len(data)]`; set `pc = 0x200`.
2. Fetch/decode with a dispatch on `op & 0xF000` (an `if` chain, a `match` statement, or a dict of handlers); implement `00E0`, `1NNN`, `6XNN`, `7XNN`, `ANNN`, `DXYN` first. That is enough for the **IBM logo** ROM.
3. `DXYN`: for each of N rows, byte `mem[I+row]`, for each of 8 bits XOR into `display[(y+row)%32][(x+col)%64]`; set VF if a lit pixel was erased. Initial coordinates wrap; sprite drawing usually clips at the edge (check the quirks test).
4. Render to the terminal: `"\x1b[H"` (cursor home) then `█`/space per pixel. Build the whole frame as one string and write it once with `sys.stdout.write`; many small prints flicker.
5. Ship the test ROMs inside the package and read them with `importlib.resources.files("chip8").joinpath("roms/ibm.ch8").read_bytes()`.

# Pitfalls

- `7XNN` must wrap at 8 bits (`& 0xFF`) and **not** touch VF.
- Increment PC _before_ executing, so jumps overwrite it.
- A pure Python loop will run a few hundred thousand instructions a second, which is plenty for CHIP-8 at 500-700 instructions a second.

# Hash map = O(1) average lookup/insert/delete

Trade memory for time: turn nested loops into one pass. In Python, `dict` and `set` are hash tables.

**Longest consecutive sequence:** put all values in a set; only start counting from `v` where `v-1` is absent. O(n).

```python
s = set(a)
best = 0
for v in s:
    if v - 1 not in s:
        n = v
        while n + 1 in s:
            n += 1
        best = max(best, n - v + 1)
```

**Prefix sum + map** (works with negatives, unlike sliding window): `sum[i..j] = P[j+1] - P[i]`. A subarray ending here sums to `k` if an earlier prefix equals `P - k`.

```python
from collections import defaultdict

# count subarrays with sum k
cnt = defaultdict(int)
cnt[0] = 1
total = ans = 0
for v in a:
    total += v
    ans += cnt[total - k]
    cnt[total] += 1

# longest subarray with sum k: store the FIRST index of each prefix
first = {0: -1}
total = best = 0
for i, v in enumerate(a):
    total += v
    if total - k in first:
        best = max(best, i - first[total - k])
    first.setdefault(total, i)
```

**Sum 0** is the `k=0` case. **XOR = K:** same with prefix XOR: `ans += cnt[x ^ k]`.

Seed `{0: 1}` / `{0: -1}` so subarrays starting at index 0 are counted.

# Parametrized tests

One test function, many cases; adding a case is one line.

```python
import pytest
from chip8 import CPU

@pytest.mark.parametrize(
    ("a", "b", "want", "want_vf"),
    [
        pytest.param(1, 2, 3, 0, id="no-carry"),
        pytest.param(255, 1, 0, 1, id="carry"),
    ],
)
def test_add_with_carry(a, b, want, want_vf):
    c = CPU()
    c.v[0], c.v[1] = a, b
    c.exec(0x8014)
    assert (c.v[0], c.v[0xF]) == (want, want_vf)
```

Each case is reported separately by its `id`, and `pytest -k carry` runs just that one. Put shared setup in a **fixture** (a function marked `@pytest.fixture` whose result is passed in by name) instead of repeating it.

1. **CPU vs machine.** CPU: registers, PC, stack, `I`, fetch/decode/execute (`step`). Machine: memory/ROM loading, display, keyboard, timers, sound, the run loop and clock. Keeping them separate makes the core testable and swappable.
2. **Interrupts.** Add an interrupt-pending flag (set by timer/keyboard threads or tasks, guarded by a lock or a queue). At the top of `step`, if pending and enabled: push `PC` (and flags), jump to a handler address, clear the flag; add a return-from-interrupt instruction. This mirrors hardware: check between instructions, save state, vector to a handler.
